# 대표 사례: 새록 SQL의 답 한 줄을 고친 이유

[새록이 소개](../README.md) | [새록 SQL 사용법](../fruits/16-natural-language-sql/README.md) | [채점 기록](../fruits/16-natural-language-sql/eval/RESULTS.md)

## 문제 정의

비전공자가 우리말로 숫자 하나를 물었을 때 SQL이 실행되고 값이 맞는 것만으로는 충분하지 않았습니다. 답이 여러 행의 표에 묻히면 무엇을 보고 판단해야 할지 다시 찾아야 합니다. 새록 SQL은 서울 생활 공공 데이터에서 질문을 조회 SQL로 바꾸고, 결과와 해석을 함께 보여 주도록 만든 도구입니다.

## 실제로 고친 한 사례

어려운 평가 세트의 h04 질문은 **“2025년 고속터미널역 승차 인원 합계는?”**이었습니다. 첫 답은 노선별 세 행과 합계 한 행을 한 표에 담았습니다. 합계 **30,869,411명**은 맞았지만 질문이 요구한 값 하나가 맨 아래에 묻혔고, 자동 채점도 기대한 한 행과 행 수가 달라 실패했습니다. [질문 원본](../fruits/16-natural-language-sql/eval/questions-hard.json)과 [판정 과정](../fruits/16-natural-language-sql/eval/RESULTS.md)에 기록돼 있습니다.

이때 채점기를 완화하지 않았습니다. **합계나 개수처럼 값 하나를 물으면 결과 표는 그 값 한 행으로 내고, 내역은 설명이나 별도 조회로 보인다**는 답 형식 기준을 스킬에 추가했습니다. 같은 질문만 다시 풀었을 때 합계 한 행을 내고 노선별 내역을 따로 보여 줘 자동 채점과 사람 판정 모두 통과했습니다. 이 수정은 SQL 계산 능력의 향상이 아니라 **맞는 결과를 읽기 쉬운 답으로 전달하는 방식**의 개선입니다.

## 어느 범위까지 확인했나

| 확인 | 결과 | 범위 |
|---|---|---|
| 기본 질문 | 20문항 통과 | 첫 채점의 19/20에서 한 문항의 채점 컬럼 기준을 고친 뒤 20/20입니다. 정답은 사람이 나중에 검토했습니다. |
| 어려운 질문 | 16문항 사람 판정 통과 | h04를 고친 뒤의 두 번째 판정입니다. 모든 문항의 자동 점수가 16/16이라는 뜻은 아닙니다. |
| 실행 경계 | 조회 SQL만 실행, 결과 최대 1,000행 | [안전 검사와 실행 방식](../fruits/16-natural-language-sql/README.md)에 명시했습니다. |

**사용 제한:** 질문과 정답 초안은 AI가 만들었고, 평가에 사용한 모델과 데이터 사전도 정해져 있습니다. 기본 20문항은 비교적 쉬운 질문입니다. 이 결과를 처음 보는 사람의 질문 전체나 다른 데이터에서의 정확도로 일반화할 수 없습니다. Claude API를 직접 부르는 터미널 방식의 답 품질은 별도로 채점하지 않았습니다.

**앞으로 추진:** 사용자가 직접 낸 질문을 모아 먼저 답의 단위와 기간, 한 행 또는 여러 행의 기대 형태를 기록합니다. 그 질문으로 스킬과 터미널 방식을 따로 실행하고 숫자 정확도와 해석의 명확성을 사람이 평가합니다. 두 방식 모두 같은 기준을 통과할 때만 답 형식 개선이 넓은 사용 상황에서도 유지된다고 말하겠습니다.
