# 새록이 1번 에이전트 PRD v1.6

- 작성일: 2026-10-15
- 상태: 스무고개 설계 확정, 시간대별 구성 구현 시작
- 대상: `Content Personalization Agent`
- 실행 환경: 1단계 Claude 웹앱 프로젝트, 이후 Claude API 앱으로 확장
- 이전 문서: [PRD v1.5](PRD-v1.5.md)

## 1. 한 문장 정의

새록이는 시간대와 사용자의 관심사에 맞춰 기술 블로그, 뉴스레터와 날씨 기반 숨은 명곡 후보를 3개씩 보여주고, 사용자가 직접 선택하게 하는 개인 콘텐츠 발견 에이전트입니다.

## 2. 해결할 문제

사용자는 출퇴근길이나 업무 중에 읽거나 들을 콘텐츠를 찾고 싶지만, 여러 출처를 직접 확인할 시간이 부족합니다. 인기순으로만 찾으면 이미 본 콘텐츠나 광고성 글이 섞이고, 왜 추천받았는지도 알기 어렵습니다.

## 3. 핵심 사용자 상황

| 시간대 | 사용 상황 | 추천 구성 |
|---|---|---|
| 07:30~09:00 | 출근길 | 음악 1개, 기술 블로그 1개, 뉴스레터 1개 |
| 09:00~18:00 | 업무 중 | 뉴스레터 3개 |
| 18:00~20:00 | 퇴근길 | 기술 블로그 3개 |
| 20:00 이후 | 자동 추천 없음 | 사용자가 직접 다시 실행할 때만 검토 |

시간대는 서울 시간 기준입니다. 해당 시간대에 처음 열었을 때 추천을 한 번 만들고, 같은 시간대에는 같은 결과를 유지합니다. 사용자가 `새로 추천`을 눌렀을 때만 다시 수집하고 추천합니다.

## 4. 콘텐츠별 규칙

### 음악

- 서울의 현재 날씨를 반영합니다.
- 서울 고정 좌표의 현재 날씨는 Open-Meteo 공개 API에서 가져오며, API 키를 저장하지 않습니다.
- 유명한 곡보다 잘 알려지지 않은 숨은 명곡을 우선합니다.
- 현재는 아침 출근길에만 1개를 추천합니다.
- 인기도 자료가 없으면 숨은 명곡이라고 단정하지 않고 확인 필요 상태를 표시합니다.

### 기술 블로그

- 사용자가 확인한 INSIGHT 목록의 공개 출처 전체를 사용합니다.
- 출근길에는 1개, 퇴근길에는 3개를 후보로 보여줍니다.
- 개발 기술뿐 아니라 기획, 데이터 분석과 마케팅 관련 기술 인사이트도 포함합니다.

### 뉴스레터

- 뉴닉 공개 아티클과 확인된 공개 뉴스레터 출처를 사용합니다.
- 업무 중에는 3개를 후보로 보여줍니다.
- 구독자 전용 원문이나 이메일 원문은 수집하지 않습니다.

## 5. 초기 취향

### 공통 관심사

- 기획
- 데이터 분석
- 마케팅
- 발라드
- 스포츠

### 유형별 취향 확장

공통 관심사는 모든 콘텐츠에 적용하고, 음악, 기술 블로그와 뉴스레터의 세부 선호는 별도로 기록합니다. 예를 들어 발라드는 음악에, 데이터 분석은 기술 블로그와 뉴스레터에 더 높은 우선순위를 줄 수 있습니다.

### 제외 항목

- 투자 권유
- 유료 콘텐츠
- 광고성 글

## 6. 추천 결과 형식

후보 하나에는 다음 세 정보만 기본으로 보여줍니다.

1. 제목
2. 한 문장으로 짧고 명확한 추천 이유
3. 원문 링크

추천 이유는 사용자의 관심사와 현재 시간대 또는 날씨를 연결해 작성합니다. 긴 요약, 과장된 인기 표현과 근거 없는 ‘숨은 명곡’ 표현은 사용하지 않습니다.

## 7. 사용자 반응

각 후보에서 다음 반응을 기록합니다.

- `읽을게요`
- `이미 읽었어요`
- `관심 없어요`

반응을 누르면 현재 화면의 후보는 바꾸지 않습니다. 반응은 다음 시간대 추천과 `새로 추천` 결과부터 반영합니다.

## 8. 데이터와 실행 흐름

`시간대 확인 → 출처 수집 → 공개 접근 여부 확인 → 중복과 제외 조건 검사 → 유형별 후보 구성 → 제목과 한 문장 이유 생성 → 3개 표시 → 사용자 반응 저장`

후보에는 최소한 다음 내부 정보를 저장합니다.

- 후보 식별자
- 콘텐츠 유형
- 제목
- 원문 링크
- 출처
- 확인 시각
- 게시 시각
- 추천에 사용한 관심사와 상황
- 인기도 근거가 있는 경우에만 인기도 값
- 사용자 반응

## 9. Claude 프로젝트 구조

Claude 웹앱 프로젝트에는 다음 자료를 넣습니다.

1. `claude/PROJECT-INSTRUCTIONS.md`
2. `docs/PRD-v1.6.md`
3. `docs/PRD-v1.5.md`
4. `AGENT-SPEC.md`
5. `data/sources.example.json`
6. `claude/session-input.template.json`
7. 사용자 취향 파일
8. 최신 후보 JSON

Claude의 역할은 후보를 새로 지어내는 것이 아니라, 수집기가 만든 후보를 시간대와 취향에 맞춰 비교하고 추천 이유를 한 문장으로 작성하는 것입니다. Claude API로 확장할 때도 이 역할과 데이터 구조를 유지합니다.

Codex에서 GitHub에 push한 뒤 Claude Code는 `git pull origin main`으로 최신 상태를 가져옵니다. Claude 웹앱 프로젝트는 저장소가 자동으로 동기화된다고 가정하지 않고, 변경된 지침과 후보 파일을 다시 업로드합니다. 자세한 절차는 [Claude 인수인계 안내](CLAUDE-HANDOFF.md)에 기록합니다.

## 10. 완료 기준

첫 완성본은 다음을 모두 만족해야 합니다.

- 서울 시간 기준으로 세 시간대를 자동 구분
- 시간대별 콘텐츠 구성에 맞춰 후보 3개 생성
- 아침에는 날씨 기반 음악 후보 1개 포함
- 확인된 INSIGHT 출처 전체와 뉴닉 공개 아티클 사용
- 투자 권유, 유료 콘텐츠와 광고성 글 제외
- 제목, 한 문장 추천 이유와 원문 링크 표시
- `읽을게요`, `이미 읽었어요`, `관심 없어요` 기록
- 현재 추천은 유지하고 다음 추천부터 피드백 반영
- `새로 추천`을 누를 때만 결과 갱신

## 11. 성공 기준

초기 사용자 확인에서 다음 네 가지를 모두 관찰합니다.

1. 추천 후보 중 하나를 실제로 읽거나 듣습니다.
2. 추천 이유가 납득됩니다.
3. 새로운 콘텐츠를 발견했다는 느낌이 듭니다.
4. 다음 날에도 다시 사용하고 싶습니다.

이 기준은 초기 가설이며, 사용자의 실제 반응을 확인한 뒤 조정합니다.
