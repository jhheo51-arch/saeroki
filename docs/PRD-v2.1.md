# 새록이 19번 열매 PRD v2.1: 새록 면접관

- 작성일: 2026-10-17
- 상태: 설계 확정(🌱 씨앗). 구현 전
- 대상: 19번 열매 `면접 연습`, 이름 `새록 면접관`, 플러그인·명령 `saerok-interview`
- 실행 환경: 내 PC의 Claude Code 플러그인(스킬 `/saerok-interview:panel`·`/saerok-interview:practice`·`/saerok-interview:compare`, 면접관 서브에이전트 5명)
  - 2026-10-17 추가: 같은 흐름의 화면 두 개. 웹(GitHub Pages `/interview/`, 내 API 키로 브라우저가 Anthropic에 바로 연결, 기록은 그 브라우저에만)과 터미널 `saerok-interview`(127.0.0.1, 기본은 `claude -p` 구독, `--api`면 API 키, 기록은 면접 폴더에만). 검사·렌더링은 Python과 같은 결과를 내는 `web/interview-core.js`가 맡음
- 참고: [AI ANTENNA, 클로드 면접관 3명 만들어 모의 면접 보는 법](https://imyoung-man.github.io/AI-ANTENNA/aitip-interview/guide.html)(2026-10-17 확인)
- 이전 문서: [PRD v2.0](PRD-v2.0.md), 원래 목록은 [PRD v01](PRD-v01.md)

## 1. 한 문장 정의

새록 면접관은 내 자기소개서·이력서·채용 공고를 면접관 5명이 각자 고정된 기준으로 심사해 근거 문장이 달린 질문과 점수를 주고, 꼬리 질문이 붙는 실전 연습과 회차별 점수 비교로 내가 나아졌는지 보여 주는 모의 면접 에이전트입니다. 합격 여부를 예측하지 않습니다.

## 2. 해결할 문제

혼자 면접을 준비하면 내 자기소개서의 어느 문장이 질문을 부르는지, 내 답이 지난번보다 나아졌는지 알기 어렵습니다. 참고 글의 방식(면접관 3명이 자기소개서를 동시에 심사)은 시작하기 쉽지만, 점수에 기준이 없어 회차마다 흔들리고, 기록이 남지 않아 비교할 수 없으며, 질문이 채용 공고나 지원 산업과 이어지지 않습니다.

### 근거

- 참고 글의 시연 결과는 면접관 3명이 각 10점 만점에 42·58·52(셋 다 보류)였지만, 점수를 매긴 기준 항목이 글에 없습니다(2026-10-17 확인). 같은 자기소개서를 다시 넣었을 때 같은 점수가 나온다는 보장이 없습니다.
- 사용자는 IT·디지털 기획 직무 취업을 준비 중이며, 17번 새록 사전 PRD([v1.7](PRD-v1.7.md))에서 이미 '면접 준비'를 보조 용도로 두었습니다(2026-10-17 확인). 용어는 정리해도 그 용어로 질문받는 연습은 아직 없습니다.
- 실제 면접 질문과 얼마나 맞는지는 아직 잰 적이 없습니다. 6장 지표로 처음 기록합니다.

## 3. 대상 사용자

IT·디지털 기획 직무를 준비하며 혼자 면접을 연습하는 사용자 본인입니다. 모의 면접을 해 줄 사람이 없거나, 한 번 받은 피드백이 다음 연습에 이어지지 않는 사람입니다.

## 4. 확정 사항

| 번호 | 질문 | 결정 |
|---:|---|---|
| 1 | 번호 | 19번. 면접·취업 관련 열매·뿌리가 없어 새로 둠 |
| 2 | 출발점 | 참고 글의 '면접관 서브에이전트 + 판정표 + 실전 연습' 뼈대를 새록이 방식으로 키움 |
| 3 | 가장 키울 점 | 근거 표시·기록·비교. 질문마다 내 문서의 원문 줄을 근거로 달고, 회차 점수를 쌓아 비교 |
| 4 | 면접관 | 5명: 압박·인사·실무(참고 글) + 임원·숫자 검증(추가) |
| 5 | 입력 | 자기소개서(필수), 채용 공고·이력서·포트폴리오(선택), 산업·직무 선택(17번 새록 사전 목록) |
| 6 | 꼬리 질문 | 실전 연습에서 질문당 꼬리 1~2번. 시작할 때 강도(순한맛·보통·매운맛) 선택, 기본 보통 |
| 7 | 점수 | 면접관별 고정 기준 항목 점수의 합으로 10점. 판정(합격권·보류·부족)은 '연습용'이라고 밝힘 |
| 8 | 답변 | 텍스트 입력 |
| 9 | 기록 | 내 PC `~/.saerok/interview/` 아래 세션 폴더에만 저장(환경 변수 `SAEROK_INTERVIEW_HOME`로 바꿈). 저장소에는 아무 기록도 두지 않음 |
| 10 | 저장소 범위 | 플러그인 코드·면접관 지침과 완전히 지어낸 '가상 지원자' 예시 1개(자동 검사용)만 |
| 11 | 실행 환경 | Claude Code 플러그인. 4번·18번처럼 저장소 마켓플레이스로 설치 |
| 12 | 이름 | 새록 면접관, 플러그인·명령 `saerok-interview` |
| 13 | 모델 | 면접관 5명은 Sonnet 5.5 서브에이전트, 판정 종합·실전 대화는 세션 모델 |
| 14 | 서류 심사 질문 수 | 면접관당 2개, 총 10개. 각 면접관은 자기 기준에서만 질문 |
| 15 | 성공 지표 | 회차 점수 상승 + 실제 면접 적중(6장) |

### 면접관 5명과 기준

면접관마다 기준 항목을 고정해, 같은 기준으로 회차를 비교합니다. 항목 점수(0~2 또는 0~3)의 합이 10점입니다.

| 면접관 | 보는 것 | 기준 항목(배점) |
|---|---|---|
| 압박 | 과장·모순·빈틈 | 주장과 근거 일치(3) · 역할 범위가 분명함(3) · 앞뒤 일관성(2) · 흔들림 없는 답(2) |
| 인사 | 지원 동기·협업·태도 | 지원 동기의 구체성(3) · 협업·갈등 해결 사례(3) · 조직 적합성(2) · 오래 다닐 근거(2) |
| 실무 | 바로 투입 가능한지 | 상황 판단(3) · 실행 순서(3) · 직무 용어를 바르게 씀(2) · 공고 요건과 연결(2) |
| 임원 | 회사 방향과 장기 포부 | 회사·산업 이해(3) · '왜 우리 회사'(3) · 3~5년 포부의 현실성(2) · 한 문장 요약력(2) |
| 숫자 검증 | 성과 수치의 출처와 계산 | 수치의 출처(3) · 계산 과정(3) · 지표 정의(2) · 비교 기준(이전·대조군)(2) |

- 서류 심사 질문 하나마다 ① 질문 ② 근거(내 문서의 원문을 따옴표와 줄 번호로) ③ 이 질문으로 확인하려는 기준 항목 ④ 좋은 답의 방향 한 줄을 씁니다. 근거 줄이 없는 질문은 '근거 없음(일반 질문)'으로 따로 표시합니다.
- 서류 점수는 문서만 보고 매긴 점수이고, 답변 점수는 실전 연습에서 매긴 점수입니다. 둘을 섞지 않습니다.
- 압박의 '흔들림 없는 답', 임원의 '한 문장 요약력'은 말로 답하는 모습을 봐야 판단할 수 있어 서류 심사에서는 '해당 없음(답변에서만 봄)'으로 두고, 실전 연습에서만 채점합니다.
- 공고가 없으면 실무의 '공고 요건과 연결', 임원의 '회사·산업 이해'는 '해당 없음(공고 없음)'으로 두고 분모에서 뺍니다. 0점으로 바꾸지 않습니다(AGENT-SPEC 3번).

## 5. 해결책: 면접 흐름

1. **서류 심사** `/saerok-interview:panel <자기소개서> [--posting 공고] [--resume 이력서] [--industry platform --role pm]`
   - 서류 폴더(2026-10-17 추가): 경로 없이 부르면 `~/.saerok/interview/서류/`에서 파일 이름(`자기소개서`·`공고-회사이름`·`이력서`·`포트폴리오`)으로 고릅니다. `자기소개서-회사이름`(2026-10-17 추가, 21번 새록 지원서 [PRD v2.2](PRD-v2.2.md) 4장 15번·10장)이 있으면 `--company 회사이름`에 그 파일을 먼저 쓰고, 없으면 이름 없는 `자기소개서`로 돌아갑니다. 공고도 이름 없는 자기소개서도 없으면 회사 이름이 붙은 자기소개서로 회사를 정합니다. 폴더가 없으면 양식 두 개를 만들고 멈추며, 양식 그대로인 파일은 쓰지 않습니다. 참고 글의 '모의면접 폴더를 직접 만들고 긴 문장을 붙여 넣는' 단계를 줄이려는 것입니다.
   - 개인정보 점검: 주민번호·전화번호·이메일 꼴을 찾으면 진행 전에 알리고 지울지 묻습니다.
   - 세션 폴더 `~/.saerok/interview/2026-10-17-<회사명 또는 이름 없음>/`를 만들고 입력 사본을 둡니다. 현재 폴더가 git 저장소 안이면 경고합니다.
   - 면접관 5명을 동시에 불러 질문 2개씩과 서류 점수를 받습니다. 산업·직무를 골랐으면 실무·숫자 검증 면접관에게 17번 새록 사전의 해당 산업·직무 핵심 용어 목록을 함께 줍니다.
   - 세션 모델이 `verdict.md`(면접관별 점수·기준 항목·질문 10개·고칠 점)와 `score.json`을 씁니다.
2. **실전 연습** `/saerok-interview:practice [세션 폴더] [--level 순한맛|보통|매운맛] [--who 압박]`
   - 서류 점수가 낮은 면접관의 질문부터 하나씩 묻고, 내 답이 기준 항목을 못 채우면 꼬리 질문을 1~2번 더합니다.
   - 질문마다 기준 항목별 답변 점수, 빠진 항목, 더 좋은 답의 뼈대를 줍니다. 내 답을 대신 써 주지 않고, 내 답의 문장을 고치는 방향으로 보여 줍니다.
   - 질문·답·점수를 세션 폴더 `practice.md`와 `score.json`에 덧붙입니다.
3. **회차 비교** `/saerok-interview:compare [세션 폴더 여러 개 또는 --last 3]`
   - `bin/saerok-interview compare`가 `score.json`만 읽어 면접관·기준 항목별 점수 변화, 반복해서 낮은 항목, 실제 면접 적중률을 텍스트·JSON으로 냅니다. 같은 입력은 언제나 같은 결과입니다.
4. **실제 면접 기록** `/saerok-interview:compare --real <세션 폴더>`로 실제로 받은 질문을 붙여 넣으면, 모의 질문과 비슷한 것을 짝지어 적중 여부를 기록합니다. 짝짓기는 AI 해석으로 표시하고 사용자가 확인한 것만 적중으로 셉니다.

## 6. 성공 지표

- 2026-11-30까지 세션 3회 이상을 하고, 같은 기준 항목으로 잰 답변 점수의 3회차 평균이 1회차보다 2점(10점 만점) 이상 오르는지 봅니다.
- 실제 면접을 본 뒤 받은 질문 중 모의 질문과 비슷했던 비율(적중률)을 기록합니다. 첫 목표는 30% 이상이고, 20% 아래면 면접관 지침과 공고 반영 방식을 다시 봅니다.
- 같은 문서로 서류 심사를 두 번 했을 때 면접관별 서류 점수 차이가 2점 이내인지 확인합니다. 넘으면 기준 항목 설명을 다듬습니다.

## 7. 가정과 위험

| 가정·위험 | 대응 |
|---|---|
| 기준 항목이 있어도 AI 채점은 회차마다 흔들릴 수 있다 | 항목마다 0·1·2(·3)점의 뜻을 지침에 적고, 같은 문서 재심사 차이를 6장에서 잼 |
| 자기소개서·답변은 개인정보다 | 기록은 `~/.saerok/interview/`에만. 저장소 안에서 실행하면 경고하고, 저장소에는 가상 지원자 예시만 둠. 외부 전송 기능 없음 |
| 점수·판정을 실제 합격 가능성으로 오해할 수 있다 | 판정마다 '연습용, 실제 면접 방식과 다를 수 있음'을 밝힘 |
| 면접관 5명 동시 실행은 사용량이 크다 | 면접관은 Sonnet. `--who`로 일부만 부를 수 있게 하고, 18번 새록 파수꾼으로 사용량을 봄 |
| 공고·회사 정보를 AI가 지어낼 수 있다 | 임원 면접관은 공고와 사용자가 넣은 자료 안에서만 회사 이야기를 하고, 없으면 '자료 없음'으로 둠(AGENT-SPEC 2번) |
| 17번 용어집과 플러그인 사본이 어긋날 수 있다 | 플러그인 안 `data/terms-lite.json`을 17번 원본에서 줄여 만들고, 원본에서 다시 만든 결과와 다르면 자동 검사가 실패 |
| 꼬리 질문이 내 답을 대신 써 주는 쪽으로 흐를 수 있다 | 더 좋은 답은 뼈대와 빠진 항목만. 완성 답안은 사용자가 요청할 때만 |

## 8. 완료 기준

- 플러그인 `saerok-interview`: 면접관 서브에이전트 5개(`agents/`), 스킬 `panel`·`practice`·`compare`, 마켓플레이스 등록
- `verdict.md`·`practice.md`·`score.json` 형식 정의와 세션 폴더 생성(`SAEROK_INTERVIEW_HOME` 지원, git 저장소 안이면 경고)
- 개인정보 꼴(주민번호·전화번호·이메일) 점검
- `bin/saerok-interview compare`가 회차별 면접관·기준 항목 점수 변화, 반복해서 낮은 항목, 적중률을 텍스트·JSON으로 출력
- 공고 없음·근거 없는 질문을 '해당 없음'·'근거 없음'으로 따로 표시
- 17번 용어집 사본과 동기화 검사
- 가상 지원자 예시(`examples/`)와 자동 검사, 루트 `test_fruits.py`에 연결
