# 새록이 AI 에이전트 제품군 PRD v01

- 작성일: 2026-10-14
- 상태: 방향 설계와 최소 공통 기반 시작
- 공개 범위: 비공개 저장소

## 1. 제품 정의

새록이는 사용자가 지정한 관심 영역에서 새로운 후보를 계속 찾고, 이미 아는 것과 관심 없는 것을 걸러낸 뒤, 현재 상황과 취향에 맞는 소수의 항목을 근거와 함께 추천하는 개인 AI 에이전트 제품군입니다.

`새`는 새로운 발견, `록`은 초록과 기록을 뜻합니다. 브랜드 문장은 `새록이, 취향을 따라 자라나는 새로운 발견`입니다.

첫 제품은 기술 블로그와 뉴스레터를 대상으로 하는 Content Personalization Agent입니다. 날씨 기반 음악 추천, 도서와 레시피 추천은 같은 발견 흐름을 검증한 뒤 추가합니다.

## 2. 해결하려는 문제

- 관심 분야가 많아도 새 항목을 매번 직접 찾기 어렵습니다.
- 인기 순위는 이미 아는 항목을 반복해서 보여줄 수 있습니다.
- 추천 이유와 출처가 없으면 취향에 맞는지 판단하기 어렵습니다.
- 여러 AI 도구를 사용하면 취향과 작업 기준이 서로 다르게 남을 수 있습니다.

## 3. 목표 사용자와 변화

관심 분야는 있지만 탐색에 많은 시간을 쓰고 싶지 않은 개인 사용자를 대상으로 합니다. 사용자는 추천을 많이 받는 대신, 오늘 확인할 가치가 있는 낯선 항목을 1개에서 3개까지 받고 그 이유를 확인할 수 있어야 합니다.

## 4. 공통 흐름

`관심 영역 설정 → 후보 수집 → 출처 확인 → 중복과 제외 조건 검사 → 비교 → 소수 추천 → 사용자 반응 기록`

조건에 맞는 후보가 없거나 출처를 확인하지 못하면 추천하지 않습니다.

## 5. 에이전트 후보 16개

| 번호 | 이름 | 제품 역할 | 분류와 상태 |
|---:|---|---|---|
| 1 | Content Personalization Agent | 취향 기반 콘텐츠 추천 | 첫 상세 제품 |
| 2 | Agno 기반 에이전트 운영 | 여러 에이전트 실행과 관리 | 제품이 아니라 개발 기반 후보 |
| 3 | Marketing Strategy Generator | 시장 자료 기반 전략 초안 | 기획형 |
| 4 | PRD Design Support Agent | 문제 정의와 PRD 작성 지원 | 기획형 |
| 5 | Data Visualization Group Chat | 분석 역할 협업과 시각화 생성 | 데이터형, 다중 에이전트는 후순위 |
| 6 | Recipe Creator | 조건과 취향 기반 레시피 생성 | 추천형 |
| 7 | Finance Agent | 시장 자료와 분석가 의견 정리 | 고위험 분석형, 투자 판단 금지 |
| 8 | Media Trend Analysis Agent | 디지털 흐름과 인플루언서 후보 탐색 | 조사형 |
| 9 | Legal Document Analysis | PDF 법률 문서 구조와 쟁점 정리 | 고위험 분석형, 법률 판단 금지 |
| 10 | Legal Document Analysis | 9번과 같은 항목 | 중복, 별도 개발하지 않음 |
| 11 | Book Recommendation Agent | 취향 기반 도서 추천 | 추천형 |
| 12 | Information Gathering | 프롬프트와 출처 기반 자료 수집 | 여러 제품이 공유할 공통 능력 |
| 13 | Plan-and-Execute | 계획을 세우고 단계별 실행 | 여러 제품이 공유할 공통 능력 |
| 14 | Reflection | 결과를 기준에 따라 검토하고 수정 | 여러 제품이 공유할 공통 능력 |
| 15 | Research Agent | 질문, 근거와 반론을 연결한 보고서 | 조사형 |
| 16 | Natural Language to SQL Agent | 자연어 요청을 SQL로 변환하고 설명 | 데이터형, 첫 버전은 읽기 전용 |

실제 사용자용 제품 후보는 중복을 제외한 11개입니다. 12번부터 14번은 공통 능력으로 구현합니다.

## 6. 첫 제품 요구사항

### 입력

- 관심 키워드와 제외 키워드
- 좋아하는 콘텐츠 예시
- 이미 알고 있는 항목
- 승인한 공개 출처
- 필요한 경우 날씨, 시간대와 사용자가 입력한 기분

### 처리

- 원문 링크, 작성자, 게시 날짜와 확인 날짜를 저장합니다.
- 이미 확인한 항목과 제외 조건에 걸린 항목을 제거합니다.
- 관심 태그와 현재 상황이 일치하는 정도를 비교합니다.
- 인기도 자료가 없으면 덜 알려졌다고 단정하지 않습니다.
- 근거가 약하면 추천을 보류합니다.

### 출력

- 한 번에 최대 3개
- 추천 이유와 일치한 조건
- 원문 링크, 출처와 날짜
- 새로움 또는 인기도 판단 근거
- `저장`, `이미 알고 있음`, `관심 없음`, `너무 유명함` 반응

## 7. 공통 기반 기능

### 지금 만드는 것

- 모델과 무관한 취향, 후보와 추천 결과 구조
- 취향과 사용자 반응을 로컬 JSON 파일에 저장
- 출처 필수값 검사와 추적 주소를 제외한 중복 제거
- 알려진 항목과 제외 조건 필터
- 관심 태그와 상황 태그 비교
- 추천 이유와 인기도 자료의 한계 표시
- 계획 후 실행, 결과 자기 검토와 실행 기록
- 자동 검사 7개
- Claude와 Codex가 함께 읽는 공통 행동 문서

### 나중에 만드는 것

- RSS와 기술 블로그 수집
- 날씨 자료 연결
- 음악과 도서 서비스 연결
- 외부 AI 모델 연결
- 예약 실행과 알림
- Agno 또는 다른 운영 기반 도입

## 8. Claude와 Codex 호환 원칙

- 제품 요구사항과 행동 규칙은 일반 Markdown과 JSON으로 관리합니다.
- `AGENTS.md`와 `CLAUDE.md`는 같은 `AGENT-SPEC.md`를 참고합니다.
- 추천과 검증 규칙을 특정 모델의 프롬프트에만 넣지 않습니다.
- 나중에 모델을 연결할 때 제공업체별 호출 부분만 분리합니다.
- 사용자 취향과 실행 기록은 모델 제공업체의 임시 기억이 아니라 프로젝트 저장소 또는 별도 데이터 저장소에 보관합니다.

## 9. 위험과 보호 기준

- 금융: 현재 자료와 출처를 표시하고 매수와 매도 결정을 대신하지 않습니다.
- 법률: 조항과 쟁점을 찾되 법적 결론을 확정하지 않습니다.
- SQL: 첫 버전은 조회문만 허용하고 수정, 삭제와 권한 변경을 막습니다.
- 자료 수집: 공개적으로 접근 가능한 출처와 이용 조건을 확인합니다.
- 추천: 인기와 품질을 같은 의미로 사용하지 않습니다.

## 10. 확인 지표

초기에는 목표값을 확정하지 않고 다음 값을 관찰합니다.

- 처음 본 항목 비율
- 추천을 열어 본 비율
- 저장한 비율
- 이미 알고 있음, 관심 없음과 너무 유명함의 비율
- 출처 또는 날짜를 확인하지 못해 추천을 보류한 건수

## 11. 개발 순서

1. Content Personalization Agent의 기술 글과 뉴스레터 추천
2. PRD Design Support Agent
3. 도서와 레시피 추천
4. Research Agent와 Media Trend Analysis Agent
5. Marketing Strategy Generator
6. Natural Language to SQL과 데이터 시각화
7. 보호 기준을 갖춘 Finance Agent와 Legal Document Analysis

## 12. 완료 기준

첫 공통 기반은 고정된 시험 자료에서 출처가 부족하거나 중복된 후보를 제외하고, 이미 아는 항목과 제외 항목을 제거하며, 최대 3개의 추천과 이유를 반환해야 합니다. 인기도 자료가 없는 항목을 덜 유명하다고 단정하지 않고 취향과 사용자 반응, 실행 결과를 파일에 남기며 자동 검사 7개가 통과하면 완료입니다.
