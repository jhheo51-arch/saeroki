## 1. 한 문장 정의

새록 지원서는 채용 공고를 읽어 요구·우대 역량, 숨은 키워드, 회사·직무 맥락을 원문 근거와 함께 정리하고, 내 PC의 경험 장부에 적힌 경험만으로 문항별 자기소개서와 이력서·경력기술서·포트폴리오를 쓰거나 내 글을 첨삭하는 에이전트입니다. 장부에 없는 경험·수치·직함은 쓰지 않습니다. 심사와 면접 질문은 19번 새록 면접관이 맡습니다.

## 2. 해결할 문제

공고마다 자기소개서를 새로 쓰면, 공고가 실제로 무엇을 원하는지 정리하는 일과 내 경험 중 무엇을 꺼낼지 고르는 일을 매번 처음부터 합니다. 범용 AI에게 맡기면 빠르지만, 내가 하지 않은 일이나 근거 없는 수치가 그럴듯하게 섞여 들어가고, 면접에서 그 문장을 설명하지 못하게 됩니다.

### 근거

- 19번 새록 면접관 PRD([v2.1](PRD-v2.1.md))는 '자기소개서 대신 쓰기'를 이번 단계에서 만들지 않는다고 정했고, 압박·숫자 검증 면접관이 과장과 출처 없는 수치를 따로 심사합니다(2026-10-17 확인). 쓰는 단계에서 근거를 붙여 두지 않으면 심사 단계에서 같은 문제가 다시 걸립니다.
- 사용자는 IT·디지털 기획 직무 취업을 준비 중입니다(사용자 입력, 2026-10-17).
- 사용자가 실제로 낸 지원서 1건(2026-10-17, 문항 6개, 초안 5판, 원문은 저장소에 두지 않음)을 다시 보니 다음 일이 손으로 반복됐습니다. 다른 회사에 쓰던 옛 문장이 회사 이름째 남아 있었고, 지표 이름('1인당'과 '계약 1건당')과 시점 표현('격차가 벌어졌다'와 '평균 아래로 내려갔다')을 사실에 맞게 여러 번 고쳤으며, 구현하지 않은 설계안을 '도입을 가정한 설계'로 따로 적어야 했습니다. 문항마다 판을 바꾸며 중복을 지우고, 직무 세부 업무가 모든 문항 어딘가에 들어갔는지 직접 확인했습니다. 4.1절은 이 사례에서 가져왔습니다. 사례가 1건이라 일반화하지 않습니다.
- 이 열매로 쓴 자기소개서가 실제로 나은지는 아직 잰 적이 없습니다. 6장 지표로 처음 기록합니다.
- 자기소개서 문항 없이 자유양식 이력서·경력기술서 PDF 하나만 받는 공고가 있습니다(사용자가 2026-10-18에 지원을 준비한 공고 1건). 이런 공고에서는 자기소개서 흐름만으로 지원서를 끝낼 수 없습니다.
- 사용자의 지원 문서 두 벌을 면접관 입장에서 비교했습니다(2026-10-18, 원문은 저장소에 두지 않음). 한 벌은 특정 공고에 맞춘 A4 이력서 1쪽·경력기술서 1쪽·포트폴리오 5쪽이고, 다른 한 벌은 공고를 정하지 않은 16:9 슬라이드 포트폴리오 10쪽(이력서 없음)입니다. 공고 맞춤형은 첫 화면에 지원 직무, 주장 한 줄, 숫자 카드, 공고 업무별 역량 표가 있어 5초 안에 '왜 이 직무인지'가 읽혔습니다. 슬라이드형은 표지와 2쪽까지 지원 직무와 숫자가 없었고, 세 직무가 섞여 방향이 흐렸으며, 증빙 이미지 쪽과 같은 내용 쪽이 분량을 채웠습니다. 두 벌의 연락처가 서로 달랐습니다. 공고 맞춤형에도 약점이 있었습니다. 첫 숫자 카드가 지원 직무와 거리가 먼 경험이었고, 가상 데이터로 계산한 수치가 첫 쪽 카드에서 실적처럼 읽혔습니다. 4.2절 양식은 맞춤형을 따르고 이 약점을 검사로 막습니다. 비교는 1명의 문서 2벌이라 일반화하지 않습니다.

## 3. 대상 사용자

IT·디지털 기획 직무를 준비하며 여러 회사에 자기소개서를 내야 하는 사용자 본인입니다. 경험은 있지만 공고마다 맞춰 고르고 글자 수에 맞추는 데 시간이 많이 들고, AI가 쓴 문장이 사실과 어긋날까 걱정하는 사람입니다.

| 1 | 양식 | 공고 하나에 맞춘 A4 세로 문서. 이력서 1쪽 + 경력기술서 1쪽, 포트폴리오 3~5쪽. 공고를 정하지 않은 범용 슬라이드형은 만들지 않음(2장 근거) |
| 2 | 근거 원칙 | 자기소개서와 같음. 사실 줄마다 장부 ID, 근거가 없으면 `[사용자 확인 필요]`, `한 일`·`설계안(도입 가정)`·`계획` 태그를 지킴. 장부에 없는 수치·직함·기간은 쓰지 않음 |
| 3 | 판마다 고정 점검 3개 | 새 판을 만들 때마다 아래 세 가지를 빠짐없이, 이 순서로 냄. ① 5초 훑기 ② 자동 필터 ③ '안 뽑으면 손해' 다시 쓰기 |
| 4 | 자연어 첨삭 | 고정 점검 밖의 피드백(문장 다듬기, 순서 바꾸기, 강조할 경험 등)은 대화로 계속 첨삭함. 첨삭이 고정 점검을 대신하지 않음 |
| 5 | 점수의 성격 | 자동 필터의 100점 점수는 'AI 판단'으로 표시하고, 실제 채용 시스템 점수나 합격 가능성 예측이 아니라고 함께 적음. 스크립트가 낸 목록(키워드 누락·약한 표현·불일치)은 점수와 나눠 보여 줌 |
| 6 | 첫 쪽 숫자 | 이력서 첫 숫자 카드는 지원 직무 역량과 이어지는 장부 수치로 둠. 설계안·가상 데이터로 계산한 수치는 첫 숫자 카드에 두지 않거나, 같은 카드 안 숫자 바로 옆에 '가상 데이터'·'설계안'을 적음 |
| 7 | 출력 | Markdown 원본 → HTML → PDF(브라우저 인쇄). PDF는 글자를 고를 수 있는 텍스트로 두고, 글을 이미지로 넣지 않음. 한 단 읽기 순서를 지켜 채용 프로그램이 위에서 아래로 읽을 수 있게 함. 사진은 공고가 요구할 때만 |
| 8 | 19번 연결 | 확정본을 19번 서류 폴더에 `이력서-회사이름.md`·`포트폴리오-회사이름.md`로 새 파일 저장. 덮어쓰지 않음 |

고정 점검 세 가지는 다음처럼 냅니다.

1. **5초 훑기**: 오늘 이력서·포트폴리오 300장을 보고 지친 채용담당자가 첫 화면을 딱 5초만 훑는다고 보고 씁니다. 시선이 지나간 순서, 읽기를 멈춘 줄(문서 줄 번호), 멈춘 이유를 한 줄씩 적습니다. 멈춘 이유가 '흥미'인지 '의문·감점'인지 나눕니다. 'AI 판단'으로 표시합니다.
2. **자동 필터**: 채용 프로그램의 자동 필터가 되어 100점 만점 점수와 감점 이유를 냅니다. 나를 떨어뜨리는 키워드는 전부 찾습니다.
   - 스크립트 목록(같은 입력이면 같은 결과): 공고의 필수·우대 역량·키워드 가운데 문서에 없는 것, 약한 표현(`참여했습니다`·`공부했습니다`·`노력했습니다`·`기초`·`수료 예정` 등, `style.md`로 더함), 숫자 없는 경력 줄, 공고 역량과 이어지지 않는 자격·항목, 5.7절의 문서 사이 불일치
   - AI 목록: 공고 맥락에서 감점될 수 있는 말과 빠진 경험. 'AI 해석'으로 표시
   - 점수는 위 두 목록을 근거로 매기고, 감점마다 어느 목록의 어느 줄 때문인지 적습니다.
3. **'안 뽑으면 손해' 다시 쓰기**: 이 회사가 나를 안 뽑으면 손해라고 느끼도록 첫 화면(머리·주장 한 줄·숫자 카드)과 감점된 줄을 다시 쓴 안을 냅니다. 장부 사실만 쓰고 줄마다 장부 ID를 답니다. 수치를 지어내거나 키우지 않습니다. 가상·설계안 표기는 지우지 않고, 실적처럼 읽히지 않는 자리로 옮기거나 숫자 옆에 붙입니다. 다시 쓴 안은 새 판 파일이고, `check`를 통과해야 확정할 수 있습니다.

## 5. 해결책: 지원서 흐름

### 5.1 경험 장부 `/saerok-apply:ledger [이력서 파일]`

- 장부 `~/.saerok/apply/ledger.md`에 경험마다 ID(`E01`…), 기간, 소속·직함, 상황, 내 역할(팀 전체 성과와 나눠서), 판단 이유, 행동(`한 일`·`설계안(도입 가정)`·`계획` 태그), 결과, 수치(지표 이름·기준 시점·비교 대상·전후 값·기간·규모·출처), 쓸 수 있는 역량 태그를 적습니다.
- 이력서를 넣으면 장부 초안을 만들되, AI가 채운 칸은 `(AI 정리, 확인 전)`으로 표시하고 사용자가 확인한 항목만 자소서에 씁니다.
- 장부는 사용자의 원본입니다. 고칠 때는 바뀐 줄을 보여 주고 확인받습니다(AGENT-SPEC 5번).

### 5.2 공고 분석 `/saerok-apply:analyze <URL | 붙여넣은 공고 | 이미지 파일> [--company 회사이름] [--industry platform --role pm]`

1. 공고 원문을 `~/.saerok/apply/<회사이름>/posting.md`에 출처 URL·확인 날짜와 함께 저장합니다. URL을 못 읽으면 실패를 알리고 붙여넣기를 요청합니다. 못 읽은 공고를 빈 공고로 다루지 않습니다(AGENT-SPEC 3번).
2. 회사 정보를 공개 웹에서 찾습니다. 공식 페이지·기사 몇 개를 링크·확인 날짜와 함께 '회사 조사' 칸에 두고, 공고에서 온 정보와 섞지 않습니다. 찾지 못하면 '자료 없음'으로 둡니다.
3. `analysis.md`를 씁니다.
   - **요구·우대 역량 표**: 역량 · 필수/우대 · 공고 원문 줄 · 맞는 장부 경험 ID · 빈 칸 여부
   - **숨은 키워드**: 반복되거나 강조된 말, 업무 설명에 숨은 역량. 모두 'AI 해석'으로 표시
   - **회사·직무 맥락**: 공고 안 정보와 회사 조사 칸(출처 있음)을 나눠 적음
   - **용어**: 공고 속 직무 용어를 17번 새록 사전 항목과 이어 뜻을 짧게 보여 줌. 사전에 없는 용어는 '사전에 없음'
4. 필수 요건의 빈 칸은 4장 17번 규칙대로 묻습니다.

### 5.3 자소서 작성 `/saerok-apply:write [--company 회사이름] [--edit 내 글 파일]`

1. 문항과 글자 수 제한(기본 공백 포함)을 받습니다.
2. 문항마다 장부 후보 2~3개를 이유와 함께 제안하고, 사용자가 고른 뒤 씁니다.
3. 문항 유형(4.1절 2번)을 먼저 정하고 그 틀로 씁니다. 초안 모드: 경험형은 두괄식 + STAR로 쓰고 4.1절 10번 경험 문단 원칙을 지킵니다. 첨삭 모드: 내 글을 고치되 바꾼 줄과 이유를 나란히 보여 주고, 새 파일 `draft-<날짜>.md`에 둡니다.
4. 문항마다 판 번호와 바꾼 점, `확정` 표시를 남깁니다(4.1절 5번).
5. 사실 문장마다 `<!-- E03 -->`처럼 장부 ID를 붙입니다. 장부에 근거가 없으면 문장 대신 `[사용자 확인 필요: 무엇이 필요한지]`를 남깁니다.
6. `bin/saerok-apply check`가 문항별 글자 수(공백 포함·제외·바이트), 제한의 90~100% 여부, 자소서 속 숫자·직함·기간이 장부에 있는지, 수치의 지표 이름·시점이 장부와 같은지, 설계안·계획을 한 일처럼 쓴 문장, 근거 ID 없는 사실 문장, 다른 회사 이름, 문항 사이 중복, 빠진 공고 역량, 경험 문단 원칙 위반(4.1절 10번), 표기 규칙 위반, 17번 용어를 사전 뜻과 다르게 쓴 곳을 텍스트·JSON으로 냅니다. 같은 입력은 언제나 같은 결과입니다.
7. 검사를 통과하면 제출용 본문(장부 ID 주석을 뺀 것)을 만들고, 사용자가 확인하면 19번 서류 폴더에 `자기소개서-회사이름.md`·`공고-회사이름.md`로 저장합니다. 같은 이름이 있으면 덮어쓰지 않고 날짜를 붙입니다.

### 5.4 화면

- 터미널 `saerok-apply`와 웹 `/apply/`는 같은 흐름(장부 → 분석 → 작성 → 검사)을 화면으로 보여 줍니다. 글자 수·사실 검사는 Python과 같은 결과를 내는 `web/apply-core.js`가 맡습니다.
- 웹은 장부·자소서를 그 브라우저에만 둡니다. 웹에서 회사 조사가 안 되면 '조사 안 됨'으로 표시합니다.
- 이력서·포트폴리오가 구현되면 같은 화면에 ⑤ 이력서·포트폴리오 탭을 더합니다. 탭은 미리보기, 고정 점검 3개, `check` 표를 나란히 보여 줍니다.

### 5.5 이력서·경력기술서 `/saerok-apply:resume --company 회사이름 [--edit 내 이력서 파일]`

1. 분석(`analysis.md`)이 없으면 먼저 `analyze`를 부릅니다. 공고가 받는 서류 형식(자유양식 PDF, 쪽수 제한, 사진 여부)을 분석에서 읽고, 없으면 묻습니다.
2. 이력서 1쪽을 이 순서로 씁니다.
   - **머리**: 지원 회사·직무, 연락처(장부의 연락처 칸 하나만 씀)
   - **주장 한 줄**: 굵은 한 문장과 근거 한 문장. 둘 다 장부 ID
   - **숫자 카드 4개**: 지표 이름·값·기간. 첫 카드는 4.2절 6번 규칙
   - **공고 업무별 역량 표**: 공고 업무 한 줄 ↔ 내 경험 한 줄(장부 ID)
   - **경력 요약**: 기간·소속·직함·한 줄
   - **자격·교육·학력·도구**: 공고와 이어지는 것을 먼저, 나머지는 줄여서
3. 경력기술서 1쪽은 경험마다 문제 → 한 일 → 결과 → `→ 직무 연결` 한 줄로 씁니다. 4.1절 10번 경험 문단 원칙을 지킵니다.
4. 첨삭 모드는 내 파일을 덮어쓰지 않고 바꾼 줄과 이유를 나란히 보여 줍니다.
5. 판마다 4.2절 고정 점검 3개를 내고, 그 밖의 첨삭은 대화로 이어 갑니다.
6. 파일은 `~/.saerok/apply/<회사이름>/resume-YYYY-MM-DD.md`(같은 날이면 `-2`, `-3`), 점검 결과는 같은 이름의 `.review.md`, 출력은 `.html`·`.pdf`입니다.

### 5.6 포트폴리오 `/saerok-apply:portfolio --company 회사이름 [--edit 내 포트폴리오 파일]`

1. A4 세로 3~5쪽으로 씁니다. 공고가 쪽수를 정하면 그것을 따릅니다.
2. 1쪽: 프로젝트 카드 3개(이름·한 줄·내 역할·숫자 하나), 공고 업무 ↔ 프로젝트(쪽 번호) 표, '만든 방식' 상자(가상 데이터인지, 어떤 도구로 만들었는지, 혼자인지 팀인지)
3. 프로젝트 쪽: 문제 → 설계·판단 이유 → 결과 표·화면 → 한계. 한계 칸은 비워 두지 않습니다.
4. 마지막 쪽: 입사 후 일하는 방식. 계획 문장은 장부의 `계획` 태그로만 씁니다.
5. 화면 캡처는 사용자가 준 파일 경로만 넣고, 캡처마다 무엇을 보여 주는지 한 줄을 붙입니다. 같은 내용 쪽이 되풀이되거나 증빙 이미지만 있는 쪽은 `check`가 표시합니다.
6. 판마다 4.2절 고정 점검 3개를 냅니다. 파일 이름은 `portfolio-YYYY-MM-DD.md`이고, 나머지는 5.5절 6번과 같습니다.

### 5.7 이력서·포트폴리오 검사 `bin/saerok-apply check <resume|portfolio 파일>`

자기소개서 검사(5.3절 6번) 가운데 장부 대조·출처·다른 회사·표기 규칙·용어는 그대로 쓰고, 다음을 더합니다. 모두 같은 입력이면 같은 결과입니다.

| 묶음 | 보는 것 |
|---|---|
| 첫 쪽 숫자 | 첫 숫자 카드의 장부 경험 역량 태그가 공고 역량과 하나도 겹치지 않으면 경고. 설계안·가상 데이터 수치가 표기 없이 카드·제목에 놓이면 오류 |
| 문서 사이 불일치 | 같은 회사 폴더의 이력서·경력기술서·포트폴리오·자기소개서 사이에서 연락처·기간·직함·날짜 표기가 다르면 오류 |
| 개수 주장 | '자격증 N개'·'프로젝트 N개'처럼 개수를 쓴 줄과 실제 목록 개수가 다르면 오류 |
| 약한 표현 | 4.2절 고정 점검 ②의 약한 표현 목록 |
| 키워드 누락 | 공고 필수·우대 역량과 키워드 가운데 문서에 없는 것 |
| 분량·형식 | 쪽수 한도, 사진·생년월일·주소 꼴(공고가 요구하지 않을 때), 같은 내용 쪽 되풀이, 글 없이 이미지만 있는 쪽 |

## 7. 가정과 위험

| 가정·위험 | 대응 |
|---|---|
| AI가 그럴듯한 경험·수치를 지어낼 수 있다 | 사실 문장마다 장부 ID, 스크립트가 숫자·직함·기간을 장부와 대조. 근거 없으면 `[사용자 확인 필요]` 칸 |
| 숨은 키워드·회사 맥락이 AI의 짐작일 수 있다 | 'AI 해석'으로 표시. 회사 조사는 출처·확인 날짜가 있는 것만 자소서에 씀(AGENT-SPEC 1·2번) |
| 공고 URL을 못 읽거나 일부만 읽을 수 있다 | 실패를 알리고 붙여넣기를 요청. 저장한 원문을 사용자가 확인 |
| 경험 장부·자소서는 개인정보다 | `~/.saerok/apply/`에만 저장. 저장소 안이면 경고, 개인정보 꼴 점검. 웹은 그 브라우저에만. 저장소에는 가상 지원자 예시만 |
| 글자 수 기준이 회사마다 다르다 | 세 가지를 모두 세고 문항마다 기준을 고름 |
| 옛 지원서 문장을 고쳐 쓰다 다른 회사 이름이 남을 수 있다 | `check`가 지금 회사가 아닌 회사 이름을 표시(4.1절 1번) |
| 맞는 수치라도 지표 이름·시점 표현이 사실과 어긋날 수 있다 | 장부에 지표 정의·시점·비교 기준을 두고 `check`가 대조(4.1절 3번) |
| 사용자가 AI 초안을 그대로 내 '내 글'이 아니게 될 수 있다 | 경험 고르기는 사용자가 하고, 첨삭 모드를 함께 둠. 19번 연습에서 그 문장을 설명할 수 있는지 확인 |
| 19번이 `자기소개서-회사이름` 파일을 고르지 못할 수 있다 | 19번 서류 폴더 고르기 규칙에 이 이름을 더하는 일을 19번 쪽 작업으로 둠(10장) |
| 17번 용어집과 플러그인 사본이 어긋날 수 있다 | 19번과 같은 방식으로 원본에서 줄여 만들고, 다시 만든 결과와 다르면 자동 검사 실패 |
| 자동 필터 점수가 실제 채용 시스템 점수나 합격 예측처럼 읽힐 수 있다 | 'AI 판단'과 '합격 예측 아님'을 점수 옆에 적고, 감점마다 근거 줄을 댐. 스크립트 목록과 나눠 보여 줌(4.2절 5번) |
| '안 뽑으면 손해' 다시 쓰기가 과장으로 흐를 수 있다 | 장부 사실과 ID만 쓰고, 다시 쓴 안도 `check`를 통과해야 확정. 수치를 키우거나 가상 표기를 지우면 오류 |
| 가상 데이터·설계안 수치가 실적처럼 읽힐 수 있다 | 첫 쪽 숫자 규칙과 검사(4.2절 6번, 5.7절) |
| 디자인한 PDF를 채용 프로그램이 순서대로 못 읽을 수 있다 | 텍스트 PDF, 한 단 읽기 순서, 글을 이미지로 넣지 않음(4.2절 7번) |

## 8. 완료 기준

- 플러그인 `saerok-apply`: 스킬 `ledger`·`analyze`·`write`, 마켓플레이스 등록
- 경험 장부·`posting.md`·`analysis.md`·`draft-*.md` 형식 정의와 `SAEROK_APPLY_HOME` 지원, git 저장소 안이면 경고, 개인정보 꼴 점검
- `bin/saerok-apply check`: 글자 수 세 가지, 90~100% 판정, 장부 대조(수치 정의·시점, 한 일·설계안 구분 포함), 근거 없는 사실 문장, 다른 회사 이름, 문항 사이 중복, 역량 커버리지, 표기 규칙, 17번 용어 검사를 텍스트·JSON으로
- 문항 유형별 틀, 문항별 판 번호·확정 표시
- 경험 문단 원칙 5가지 검사(상황·행동 비중, 내 역할, 판단 이유, 확인 가능한 성과, 직무 연결)
- 짧은 칸(기관명·활동내용) 채우기와 칸별 글자 수·근거 ID 검사
- 이미지 공고를 글로 옮기고 `(이미지에서 옮김, 확인 전)` 표시, 확인 전 분석 차단
- 공고 읽기 실패·회사 조사 없음·사전에 없는 용어를 각각 따로 표시
- 19번 서류 폴더로 새 이름 저장(덮어쓰기 없음)
- 터미널 `saerok-apply`와 웹 `/apply/`, Python과 같은 결과를 내는 `web/apply-core.js`
- 17번 용어집 사본 동기화 검사
- 가상 지원자 예시(`examples/`)와 자동 검사, 루트 `test_fruits.py`에 연결
- 스킬 `resume`·`portfolio`: 4.2절 양식, 판마다 고정 점검 3개(`.review.md`), Markdown → HTML → 텍스트 PDF
