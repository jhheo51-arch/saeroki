# 새록이 21번 열매 PRD v2.2: 새록 지원서

- 작성일: 2026-10-17
- 상태: 설계 확정(🌱 씨앗). 구현 전
- 대상: 21번 열매 `지원서 작성`, 이름 `새록 지원서`, 플러그인·명령 `saerok-apply`
- 실행 환경: 세 가지 입구, 같은 규칙. ① Claude Code 플러그인 스킬 `/saerok-apply:ledger`·`/saerok-apply:analyze`·`/saerok-apply:write` ② 터미널 `saerok-apply`(127.0.0.1, 기본은 `claude -p` 내 구독, 기록은 `~/.saerok/apply/`) ③ 웹 화면(GitHub Pages `/apply/`, 내 API 키로 브라우저가 Anthropic에 바로 연결, 기록은 그 브라우저에만). 구현 순서는 플러그인 → 화면

- 이전 문서: [PRD v2.1](PRD-v2.1.md), 원래 목록은 [PRD v01](PRD-v01.md)

## 1. 한 문장 정의

새록 지원서는 채용 공고를 읽어 요구·우대 역량, 숨은 키워드, 회사·직무 맥락을 원문 근거와 함께 정리하고, 내 PC의 경험 장부에 적힌 경험만으로 문항별 자기소개서 초안을 쓰거나 내 글을 첨삭하는 에이전트입니다. 장부에 없는 경험·수치·직함은 쓰지 않습니다. 심사와 면접 질문은 19번 새록 면접관이 맡습니다.

## 2. 해결할 문제

공고마다 자기소개서를 새로 쓰면, 공고가 실제로 무엇을 원하는지 정리하는 일과 내 경험 중 무엇을 꺼낼지 고르는 일을 매번 처음부터 합니다. 범용 AI에게 맡기면 빠르지만, 내가 하지 않은 일이나 근거 없는 수치가 그럴듯하게 섞여 들어가고, 면접에서 그 문장을 설명하지 못하게 됩니다.

### 근거

- 19번 새록 면접관 PRD([v2.1](PRD-v2.1.md))는 '자기소개서 대신 쓰기'를 이번 단계에서 만들지 않는다고 정했고, 압박·숫자 검증 면접관이 과장과 출처 없는 수치를 따로 심사합니다(2026-10-17 확인). 쓰는 단계에서 근거를 붙여 두지 않으면 심사 단계에서 같은 문제가 다시 걸립니다.
- 사용자는 IT·디지털 기획 직무 취업을 준비 중입니다(사용자 입력, 2026-10-17).
- 사용자가 실제로 낸 지원서 1건(2026-10-17, 문항 6개, 초안 5판, 원문은 저장소에 두지 않음)을 다시 보니 다음 일이 손으로 반복됐습니다. 다른 회사에 쓰던 옛 문장이 회사 이름째 남아 있었고, 지표 이름('1인당'과 '계약 1건당')과 시점 표현('격차가 벌어졌다'와 '평균 아래로 내려갔다')을 사실에 맞게 여러 번 고쳤으며, 구현하지 않은 설계안을 '도입을 가정한 설계'로 따로 적어야 했습니다. 문항마다 판을 바꾸며 중복을 지우고, 직무 세부 업무가 모든 문항 어딘가에 들어갔는지 직접 확인했습니다. 4.1절은 이 사례에서 가져왔습니다. 사례가 1건이라 일반화하지 않습니다.
- 이 열매로 쓴 자기소개서가 실제로 나은지는 아직 잰 적이 없습니다. 6장 지표로 처음 기록합니다.

## 3. 대상 사용자

IT·디지털 기획 직무를 준비하며 여러 회사에 자기소개서를 내야 하는 사용자 본인입니다. 경험은 있지만 공고마다 맞춰 고르고 글자 수에 맞추는 데 시간이 많이 들고, AI가 쓴 문장이 사실과 어긋날까 걱정하는 사람입니다.

## 5. 해결책: 지원서 흐름

### 5.1 경험 장부 `/saerok-apply:ledger [이력서 파일]`

- 장부 `~/.saerok/apply/ledger.md`에 경험마다 ID(`E01`…), 기간, 소속·직함, 상황, 내 역할(팀 전체 성과와 나눠서), 판단 이유, 행동(`한 일`·`설계안(도입 가정)`·`계획` 태그), 결과, 수치(지표 이름·기준 시점·비교 대상·전후 값·기간·규모·출처), 쓸 수 있는 역량 태그를 적습니다.
- 이력서를 넣으면 장부 초안을 만들되, AI가 채운 칸은 `(AI 정리, 확인 전)`으로 표시하고 사용자가 확인한 항목만 자소서에 씁니다.
- 장부는 사용자의 원본입니다. 고칠 때는 바뀐 줄을 보여 주고 확인받습니다(AGENT-SPEC 5번).

### 5.2 공고 분석 `/saerok-apply:analyze <URL | 붙여넣은 공고 | 이미지 파일> [--company 회사이름] [--industry platform --role pm]`

1. 공고 원문을 `~/.saerok/apply/<회사이름>/posting.md`에 출처 URL·확인 날짜와 함께 저장합니다. URL을 못 읽으면 실패를 알리고 붙여넣기를 요청합니다. 못 읽은 공고를 빈 공고로 다루지 않습니다(AGENT-SPEC 3번).
2. 회사 정보를 공개 웹에서 찾습니다. 공식 페이지·기사 몇 개를 링크·확인 날짜와 함께 '회사 조사' 칸에 두고, 공고에서 온 정보와 섞지 않습니다. 찾지 못하면 '자료 없음'으로 둡니다.
3. `analysis.md`를 씁니다.
   - **요구·우대 역량 표**: 역량 · 필수/우대 · 공고 원문 줄 · 맞는 장부 경험 ID · 빈 칸 여부
   - **숨은 키워드**: 반복되거나 강조된 말, 업무 설명에 숨은 역량. 모두 'AI 해석'으로 표시
   - **회사·직무 맥락**: 공고 안 정보와 회사 조사 칸(출처 있음)을 나눠 적음
   - **용어**: 공고 속 직무 용어를 17번 새록 사전 항목과 이어 뜻을 짧게 보여 줌. 사전에 없는 용어는 '사전에 없음'
4. 필수 요건의 빈 칸은 4장 17번 규칙대로 묻습니다.

### 5.3 자소서 작성 `/saerok-apply:write [--company 회사이름] [--edit 내 글 파일]`

1. 문항과 글자 수 제한(기본 공백 포함)을 받습니다.
2. 문항마다 장부 후보 2~3개를 이유와 함께 제안하고, 사용자가 고른 뒤 씁니다.
3. 문항 유형(4.1절 2번)을 먼저 정하고 그 틀로 씁니다. 초안 모드: 경험형은 두괄식 + STAR로 쓰고 4.1절 10번 경험 문단 원칙을 지킵니다. 첨삭 모드: 내 글을 고치되 바꾼 줄과 이유를 나란히 보여 주고, 새 파일 `draft-<날짜>.md`에 둡니다.
4. 문항마다 판 번호와 바꾼 점, `확정` 표시를 남깁니다(4.1절 5번).
5. 사실 문장마다 `<!-- E03 -->`처럼 장부 ID를 붙입니다. 장부에 근거가 없으면 문장 대신 `[사용자 확인 필요: 무엇이 필요한지]`를 남깁니다.
6. `bin/saerok-apply check`가 문항별 글자 수(공백 포함·제외·바이트), 제한의 90~100% 여부, 자소서 속 숫자·직함·기간이 장부에 있는지, 수치의 지표 이름·시점이 장부와 같은지, 설계안·계획을 한 일처럼 쓴 문장, 근거 ID 없는 사실 문장, 다른 회사 이름, 문항 사이 중복, 빠진 공고 역량, 경험 문단 원칙 위반(4.1절 10번), 표기 규칙 위반, 17번 용어를 사전 뜻과 다르게 쓴 곳을 텍스트·JSON으로 냅니다. 같은 입력은 언제나 같은 결과입니다.
7. 검사를 통과하면 제출용 본문(장부 ID 주석을 뺀 것)을 만들고, 사용자가 확인하면 19번 서류 폴더에 `자기소개서-회사이름.md`·`공고-회사이름.md`로 저장합니다. 같은 이름이 있으면 덮어쓰지 않고 날짜를 붙입니다.

### 5.4 화면

- 터미널 `saerok-apply`와 웹 `/apply/`는 같은 흐름(장부 → 분석 → 작성 → 검사)을 화면으로 보여 줍니다. 글자 수·사실 검사는 Python과 같은 결과를 내는 `web/apply-core.js`가 맡습니다.
- 웹은 장부·자소서를 그 브라우저에만 둡니다. 웹에서 회사 조사가 안 되면 '조사 안 됨'으로 표시합니다.

## 6. 성공 지표

- 2026-11-30까지 이 열매로 쓴 자기소개서를 실제 공고 3곳 이상에 내고, 서류 통과 여부를 기록합니다.
- 예전에 내가 쓴 자기소개서와 이 열매로 쓴 자기소개서를 19번 `/saerok-interview:panel`로 같은 공고에 대해 심사해, 면접관 5명 평균 서류 점수가 오르는지 봅니다. 특히 압박·숫자 검증 점수를 따로 봅니다.
- 제출본마다 `check` 결과에서 근거 없는 문장·수치 0개, 글자 수 초과 0건이어야 합니다.

## 7. 가정과 위험

| 가정·위험 | 대응 |
|---|---|
| AI가 그럴듯한 경험·수치를 지어낼 수 있다 | 사실 문장마다 장부 ID, 스크립트가 숫자·직함·기간을 장부와 대조. 근거 없으면 `[사용자 확인 필요]` 칸 |
| 숨은 키워드·회사 맥락이 AI의 짐작일 수 있다 | 'AI 해석'으로 표시. 회사 조사는 출처·확인 날짜가 있는 것만 자소서에 씀(AGENT-SPEC 1·2번) |
| 공고 URL을 못 읽거나 일부만 읽을 수 있다 | 실패를 알리고 붙여넣기를 요청. 저장한 원문을 사용자가 확인 |
| 경험 장부·자소서는 개인정보다 | `~/.saerok/apply/`에만 저장. 저장소 안이면 경고, 개인정보 꼴 점검. 웹은 그 브라우저에만. 저장소에는 가상 지원자 예시만 |
| 글자 수 기준이 회사마다 다르다 | 세 가지를 모두 세고 문항마다 기준을 고름 |
| 옛 지원서 문장을 고쳐 쓰다 다른 회사 이름이 남을 수 있다 | `check`가 지금 회사가 아닌 회사 이름을 표시(4.1절 1번) |
| 맞는 수치라도 지표 이름·시점 표현이 사실과 어긋날 수 있다 | 장부에 지표 정의·시점·비교 기준을 두고 `check`가 대조(4.1절 3번) |
| 사용자가 AI 초안을 그대로 내 '내 글'이 아니게 될 수 있다 | 경험 고르기는 사용자가 하고, 첨삭 모드를 함께 둠. 19번 연습에서 그 문장을 설명할 수 있는지 확인 |
| 19번이 `자기소개서-회사이름` 파일을 고르지 못할 수 있다 | 19번 서류 폴더 고르기 규칙에 이 이름을 더하는 일을 19번 쪽 작업으로 둠(10장) |
| 17번 용어집과 플러그인 사본이 어긋날 수 있다 | 19번과 같은 방식으로 원본에서 줄여 만들고, 다시 만든 결과와 다르면 자동 검사 실패 |

## 8. 완료 기준

- 플러그인 `saerok-apply`: 스킬 `ledger`·`analyze`·`write`, 마켓플레이스 등록
- 경험 장부·`posting.md`·`analysis.md`·`draft-*.md` 형식 정의와 `SAEROK_APPLY_HOME` 지원, git 저장소 안이면 경고, 개인정보 꼴 점검
- `bin/saerok-apply check`: 글자 수 세 가지, 90~100% 판정, 장부 대조(수치 정의·시점, 한 일·설계안 구분 포함), 근거 없는 사실 문장, 다른 회사 이름, 문항 사이 중복, 역량 커버리지, 표기 규칙, 17번 용어 검사를 텍스트·JSON으로
- 문항 유형별 틀, 문항별 판 번호·확정 표시
- 경험 문단 원칙 5가지 검사(상황·행동 비중, 내 역할, 판단 이유, 확인 가능한 성과, 직무 연결)
- 짧은 칸(기관명·활동내용) 채우기와 칸별 글자 수·근거 ID 검사
- 이미지 공고를 글로 옮기고 `(이미지에서 옮김, 확인 전)` 표시, 확인 전 분석 차단
- 공고 읽기 실패·회사 조사 없음·사전에 없는 용어를 각각 따로 표시
- 19번 서류 폴더로 새 이름 저장(덮어쓰기 없음)
- 터미널 `saerok-apply`와 웹 `/apply/`, Python과 같은 결과를 내는 `web/apply-core.js`
- 17번 용어집 사본 동기화 검사
- 가상 지원자 예시(`examples/`)와 자동 검사, 루트 `test_fruits.py`에 연결
