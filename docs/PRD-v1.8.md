# 새록이 16번 열매 PRD v1.8: 새록 SQL

- 작성일: 2026-10-16
- 상태: 스무고개 설계 확정, 구현 시작(🌸 꽃)
- 대상: 16번 열매 `SQL 관련 Agent`, 이름 `새록 SQL`
- 실행 환경: 내 PC의 PowerShell에서 `saerok-sql`로 여는 대화형 터미널, Claude API 사용
- 이전 문서: [PRD v1.7](PRD-v1.7.md), 원래 목록은 [PRD v01](PRD-v01.md)

## 1. 한 문장 정의

새록 SQL은 비전공 직원이 우리말로 물으면 서울 생활 공공 데이터에 맞는 SQL을 만들어 실행하고 결과와 풀이를 함께 보여 주며, 받은 SQL을 붙여 넣으면 무엇을 하는 쿼리인지 쉬운 말로 풀어 주는 터미널 에이전트입니다.

## 2. 해결할 문제

입사하면 대시보드에 없는 숫자를 직접 뽑아야 하거나, 분석가가 준 SQL을 읽어야 하는 순간이 옵니다. SQL을 모르면 매번 남에게 부탁해야 하고, SQL을 받아도 무엇을 계산했는지 확인하기 어렵습니다. 새록 SQL은 질문을 SQL로 바꾸는 일과 SQL을 우리말로 푸는 일을 한 화면에서 해 주고, 가정과 한계를 드러내 결과를 검토할 수 있게 합니다.

## 3. 스무고개 확정 사항

| 번호 | 질문 | 결정 |
|---:|---|---|
| 1 | 주 용도 | 입사 후 업무(비전공 직원이 직접 숫자를 뽑고 SQL을 이해) |
| 2 | 방향 | 자연어→SQL과 SQL→자연어 풀이 둘 다 |
| 3 | 데이터 | 공공 데이터 |
| 4 | 두뇌 | Claude API |
| 5 | 실행 환경 | Claude Code처럼 PowerShell에서 여는 대화형 터미널 |
| 6 | DB 엔진 | DuckDB |
| 7 | 데이터셋 | 서울 생활 데이터 묶음(지하철, 따릉이, 날씨, 배달, 카페·상가, 보안등, 행정동) |
| 8 | 결과 | SQL, 결과표, 쉬운 풀이 |
| 9 | 화면 형태 | `claude`를 쳤을 때와 같은 대화형 터미널. Claude Code를 역분석하지 않고 공개 파이썬 도구로 새로 만듦 |
| 10 | 안전 | 읽기 전용, 결과 최대 1,000행 |
| 11 | 애매한 질문 | 가정을 밝히고 실행 |
| 12 | 데이터 사전 | 표·컬럼의 한글 설명 파일 |
| 13 | 명령 이름 | `saerok-sql`, 화면 이름 `새록 SQL` |
| 14 | 모델 | Claude Sonnet 5.5, `/model`로 변경 가능 |
| 15 | 기록 | 내 PC에만 기록하고, `/export`·`/import`로 다른 PC에 옮김 |
| 16 | 풀이 입력 | 자동 구분: `SELECT`·`WITH`로 시작하면 풀이, 아니면 질문. `/explain 파일.sql`도 지원 |
| 17 | 데이터 보관 | 압축(Parquet)해 저장소에 포함, 출처와 이용 조건을 함께 적음 |
| 18 | API 키 | Windows 자격 증명 관리자에 보관 |
| 19 | 자기 검토 | 실행 오류는 자동 수정 최대 2번, 0행·수상한 값은 고치지 않고 `검토 필요` 표시 |
| 20 | 완료 기준 | 자동 검사에 더해 예시 질문 20개 채점(API 비용이 들어 필요할 때만 실행) |

### 3-1. 무료 방식 추가(2026-10-16)

사용자가 API 요금 없이 쓰기를 원해 Claude Code 스킬 방식을 더했습니다. Claude Code에서 `/saerok-sql 질문`으로 부르면 지금 대화하는 Claude가 데이터 사전을 읽고 SQL을 쓰며, 실행은 `saerok-sql --run`(AI 없음)으로만 해서 같은 안전 검사·읽기 전용·행 제한·기록을 거칩니다. 사용자의 Claude 요금제 사용량에는 포함되지만 API 키와 추가 요금은 없습니다. API를 쓰는 `saerok-sql` 대화형 터미널은 그대로 둡니다.

## 4. 화면과 흐름

```text
PS> saerok-sql
╭─ 새록 SQL ─────────────────────────────────────╮
│ 서울 생활 데이터 7묶음 · 모델 Sonnet 5.5 · 읽기 전용 │
│ /help 도움말 · /tables 표 목록 · /exit 끝내기       │
╰────────────────────────────────────────────────╯
> 2025년에 따릉이를 가장 많이 탄 동 5곳은?
```

1. 입력을 받습니다. `SELECT`·`WITH`로 시작하면 풀이 모드, 아니면 질문 모드입니다.
2. 질문 모드: 데이터 사전과 질문을 Claude에 보내 SQL과 가정을 받습니다.
3. 안전 검사를 통과한 SQL만 읽기 전용 DuckDB에서 실행합니다.
4. 결과를 보여 줍니다: 가정 → SQL → 결과표(최대 1,000행 중 화면에는 앞 20행) → 줄별 풀이 → 한계·주의.
5. 실행 오류면 오류를 Claude에 돌려주고 최대 2번 고칩니다. 그래도 실패하면 실패를 그대로 보여 줍니다.
6. 기록 파일에 질문, SQL, 결과 행 수, 상태를 남깁니다.

### 명령

| 명령 | 동작 |
|---|---|
| `/help` | 도움말 |
| `/tables` | 표 목록과 한 줄 설명 |
| `/describe 표이름` | 컬럼, 단위, 기간, 주의점 |
| `/explain 파일.sql` | 파일의 SQL 풀이 |
| `/history` | 최근 기록 |
| `/export 파일`·`/import 파일` | 기록을 다른 PC로 옮기기 |
| `/model 이름` | 모델 바꾸기 |
| `/key` | API 키 다시 등록 |
| `/exit` | 끝내기 |

## 5. 데이터

- 태블로 프로젝트(TTJ)에서 정제한 서울 생활 데이터(2024-Q1~2026-Q3, 데이터마다 공개 범위 다름)를 표마다 Parquet으로 압축해 `fruits/16-natural-language-sql/data/`에 둡니다.
- 데이터 사전(`data/dictionary.json`)에 표마다 설명, 단위(행 하나가 무엇인지), 기간, 출처, 이용 조건, 주의점, 컬럼별 한글 뜻을 적습니다. AI는 이 사전만 보고 SQL을 씁니다.
- 원본의 한계(예: 따릉이 2025년 2월은 16일치뿐, 배달은 주문 수가 아니라 사용일수)는 사전의 주의점에 넣고, 해당 표를 쓴 답의 `한계·주의`에 그대로 보여 줍니다.
- 각 데이터의 이용 조건(공공누리 유형 등)을 출처 페이지에서 확인해 적습니다. 저장소에 다시 배포할 수 없는 데이터는 넣지 않습니다.

## 6. 안전 원칙

- DuckDB를 읽기 전용으로 엽니다.
- 실행 전에 SQL을 검사해 문장 하나의 `SELECT`·`WITH`만 허용하고, 쓰기·삭제·변경·파일 읽기와 쓰기(`COPY`, `ATTACH`, `read_csv` 등 외부 접근 함수)·설정 변경을 막습니다.
- 결과는 최대 1,000행까지만 가져옵니다.
- API 키는 Windows 자격 증명 관리자에만 두고 파일·기록·화면에 남기지 않습니다.
- 기록 파일에는 질문·SQL·결과 행 수·상태만 남기고 결과 값 전체는 남기지 않습니다.
- AI가 만든 SQL과 풀이는 `AI가 작성`으로 표시하고, 가정을 숨기지 않습니다. 실패나 빈 결과를 0이나 정상으로 바꾸지 않습니다.

## 7. 완료 기준

- PowerShell에서 `saerok-sql`로 대화형 화면이 열림
- 질문하면 가정, SQL, 결과표, 풀이, 한계가 나옴
- SQL을 붙여 넣거나 `/explain 파일.sql`로 넣으면 풀이가 나옴
- 쓰기·삭제·외부 파일 접근 SQL은 실행 전에 막힘
- 실행 오류는 최대 2번 자동 수정, 실패는 그대로 표시
- 기록이 내 PC에 남고 `/export`·`/import`로 옮겨짐
- API 키가 Windows 자격 증명 관리자에 보관됨
- 데이터 사전이 모든 표와 컬럼을 설명함
- 자동 검사(안전 검사, 실행, 입력 구분, 기록, 화면 흐름)는 API 없이 통과
- 예시 질문 20개 채점 스크립트와 정답 결과가 있음
- Claude Code 스킬 `/saerok-sql`로 API 키 없이 질문·풀이가 됨

## 8. 이번 단계에서 만들지 않는 것

- 회사 DB·BigQuery 등 실제 저장소 연결
- 사용자가 올린 CSV
- 차트
- 쓰기·수정 쿼리
- 웹 화면
