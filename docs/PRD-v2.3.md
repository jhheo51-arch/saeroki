# 새록이 22번 열매 PRD v2.3: 새록 가지치기

- 작성일: 2026-11-04
- 상태: 설계 확정(🌱 씨앗). 구현 전
- 대상: 22번 열매 `메모리 컨트롤러`, 이름 `새록 가지치기`, 플러그인·명령 `saerok-memory`
- 갈래: 돌봄. 18번 새록 파수꾼(토큰 감시)과 나란히 둠
- 이전 문서: [PRD v2.2](PRD-v2.2.md), 원래 목록은 [PRD v01](PRD-v01.md)

## 1. 한 문장 정의

새록 가지치기는 Claude 기억 파일, 작업 폴더의 옛 버전 파일, 오래된 Claude 세션 기록에서 줄이거나 치울 후보를 규칙으로 골라 대시보드에 보여 주고, 사용자가 누른 것만 백업하거나 Windows 휴지통으로 옮기는 메모리 감축 에이전트입니다.

## 2. 해결할 문제

Claude Code는 매 세션 기억 목차(`MEMORY.md`)를 읽습니다. 프로젝트가 늘고 진행 기록이 목차 줄에 계속 덧붙으면서 매 세션 읽는 양이 커지고, 끝난 지원·중단한 프로젝트도 목차에 남습니다. 작업 폴더에는 자소서 v1~v5, 포트폴리오 v20대처럼 새 버전이 있는 옛 파일이 쌓이고, 세션 기록도 지우지 않고 남습니다.

### 근거

2026-11-04 사용자 PC에서 잰 값(사용자 본인 사례 1개).

| 대상 | 측정값 |
|---|---|
| 기억 목차 `MEMORY.md` | 9,433바이트, 37줄. 가장 긴 줄 1,537자, 다음 1,394자 |
| 기억 파일 전체 | 37개, 약 180KB. 가장 큰 파일 20KB(현대백화점), 18KB(한독모터스) |
| 작업 폴더 이름에 `vN`이 든 파일 | 1,057개, 535MB(`.git`, `node_modules` 제외) |
| Claude 세션 기록 `~/.claude/projects` | 3.4GB, `.jsonl` 491개(3.3GB). 14일 넘은 기록 149MB |

목차 한 줄이 1,500자를 넘는 것은 진행 기록이 목차에 쌓였기 때문입니다. 본문 파일에 있어야 할 내용입니다.

## 3. 대상 사용자

새록이를 만드는 사용자 본인처럼 Claude Code로 여러 프로젝트를 동시에 굴려 기억과 파일이 빠르게 쌓이는 사람입니다.

## 5. 해결책(초안)

판정은 결정적 규칙(같은 입력이면 같은 후보)으로 하고, AI는 목차 줄 요약 문장을 제안할 때만 씁니다.

### 5.1 기억 파일

| 검사 | 규칙 | 제안 |
|---|---|---|
| 목차 줄 다이어트 | 목차 한 줄이 150자를 넘음 | 짧은 요약으로 바꾸고 넘친 진행 기록은 본문 파일 끝으로 옮김 |
| 목차 예산 | 목차가 4,000바이트를 넘음. 150자부터 5자씩 낮추며 "그 길이를 넘는 줄을 모두 제안대로 줄이면" 몇 바이트인지 세고, 4,000바이트 안에 드는 가장 긴 길이를 예산으로 정함. 60자까지 내려도 안 되면 못 맞춘다고 알림 | 예산 길이를 넘는 줄도 줄이기 후보로 두고, 여러 줄을 한 번에 적용(기록 한 건, 되돌리기 한 번) |
| 끝난 기억 보관 | 본문에 적힌 마감일이 30일 넘게 지났고 그동안 수정이 없음 | `_archive/`로 옮기고 목차에서 뺌 |
| 중복 | 같은 저장소·폴더 경로나 같은 커밋을 두 파일이 적음 | 두 파일을 나란히 보여 줌(합치기는 사용자 판단) |
| 낡은 사실 | 본문의 로컬 경로가 지금 없음 | `확인 필요`로 표시 |

줄이기 제안은 설명을 쉼표 마디로 나눠 앞에서부터 남기며, 괄호 안 쉼표에서는 나누지 않습니다.

기억 파일은 휴지통으로 보내지 않고 보관만 합니다. 바꾸기 전 `~/.saerok/memory/backup/<날짜>/`에 원본을 복사합니다.

### 5.2 작업 폴더 옛 버전

- 같은 줄기 이름(예: `자소서_v3.docx`, `자소서_v5.docx`)에서 가장 높은 버전과 바로 앞 버전은 남기고, 나머지 중 14일 넘게 수정이 없는 것만 후보로 둡니다.
- git이 추적하는 파일은 제외합니다(기록이 git에 있음).
- 보호 목록(이름에 `제출`·`최종`·`final`, 바탕화면 아래 파일)은 후보에서 뺍니다.

### 5.3 세션 기록

- 마지막 수정 뒤 30일이 지난 `.jsonl`을 후보로 둡니다. 지금 열린 세션은 제외합니다.
- 18번 파수꾼이 같은 기록을 읽으므로, 버리기 전에 파수꾼 집계(숫자만)를 먼저 내보냅니다.

### 5.4 화면

`/saerok-memory:dashboard`로 로컬 웹 화면을 엽니다.

- 지금: 대상별 용량, 목차 크기와 가장 긴 줄, 매 세션 읽는 기억의 어림 토큰
- 후보: 검사별 후보 목록과 이유, 체크 후 `적용` 버튼. 목차 줄은 프로젝트별 예산 상자에서 "지금 바이트 → 고른 줄 적용 뒤 바이트"를 고친 문장 기준으로 바로 계산
- 기록: 적용 내역, 확보한 용량, `되돌리기`(백업 복원, 휴지통 항목은 복원 안내). 위에 적용 건수, 되돌린 비율, 목차에서 줄인 바이트, 휴지통으로 보낸 용량 집계

## 6. 성공 지표

- 목차 `MEMORY.md` 9,433바이트 → 4,000바이트 이하, 가장 긴 줄 1,537자 → 150자 이하
- 적용 뒤 되돌린 비율 10% 이하(잘못 고른 후보가 적다는 뜻)

## 7. 완료 기준

1. 세 대상(기억 파일, 옛 버전, 세션 기록)의 후보를 규칙대로 고르는 검사가 있고, 같은 입력이면 같은 후보를 냄(단위 검사로 확인)
2. 보호 목록, git 추적 파일, 가장 높은 버전과 바로 앞 버전, 지금 열린 세션이 후보에 들지 않음(단위 검사로 확인)
3. 대시보드 지금·후보·기록 탭이 열리고, 체크한 것만 적용됨
4. 기억 파일은 백업 뒤 바뀌고 되돌리기로 원래대로 돌아옴. 파일 버리기는 Windows 휴지통으로만 감
5. 사용자 PC에서 한 번 돌려 `MEMORY.md`가 4,000바이트 이하가 됨
6. Stop 훅은 대시보드 버튼으로 켜고 끔

## 8. 이번 단계에서 만들지 않는 것

- 자동 정리(사용자가 누르지 않은 적용)
- 휴지통 비우기, 영구 삭제
- 기억 내용을 AI가 마음대로 다시 쓰기(요약 문장은 제안만, 적용 전 원문과 나란히 보여 줌)
