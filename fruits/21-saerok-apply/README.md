# 🍎 21 새록 지원서 (공고 분석·자기소개서)

<img src="../../assets/characters/saeroki-apply.png" alt="연필을 들고 지원서 봉투를 낀 새록이" width="140" align="right">

채용 공고를 분석하고, 내 경험 장부에 적힌 경험만으로 문항별 자기소개서를 쓰거나 첨삭합니다. 글자 수·장부 대조·다른 회사 이름·중복·역량 커버리지는 AI가 아니라 스크립트가 검사하고, 확정본은 19번 [새록 면접관](../19-saerok-interview) 서류 폴더로 넘겨 심사받습니다.

- 상태: 🍎 열매(2026-10-20 첫 버전 완성: 자기소개서, 이력서, 포트폴리오 검사와 제출)
- 설계: [PRD v2.2](../../docs/PRD-v2.2.md)(2026-10-18 개정: 이력서·경력기술서·포트폴리오 설계 추가, 2026-10-20 검사기 구현)
- 공통 원칙: [AGENT-SPEC.md](../../AGENT-SPEC.md)

## 바로 쓰기

| 어디서 | 여는 법 | 키·기록 |
|---|---|---|
| 터미널 | `saerok-apply` | 지원 화면이 내 PC(127.0.0.1)에서 열립니다. API 키 없이 Claude Code에 로그인한 내 Claude 구독 사용량으로 돌고, 기록은 지원 폴더(`~/.saerok/apply/`)에 남습니다. API 키로 돌리려면 `saerok-apply --api`(키는 Windows 자격 증명 관리자) |
| 웹 | [`web/index.html`](web/index.html) | 내 Claude API 키를 화면에 넣으면 브라우저가 Anthropic에 바로 연결합니다. 장부와 초안은 그 브라우저에만 남고, 제출본은 파일로 내려받습니다 |
| Claude Code | `/saerok-apply:ledger` → `/saerok-apply:analyze` → `/saerok-apply:write` | 아래 '쓰는 순서' |

터미널 명령은 한 번만 설치하면 됩니다.

```bash
pip install -e "fruits/21-saerok-apply[keyring]"
saerok-apply
```

화면에는 탭이 네 개입니다. **① 장부**에서 경험 장부를 고치고 형식을 점검하고, **② 공고**에서 공고(붙여넣기·캡처 이미지)를 저장해 분석하고, **③ 작성**에서 문항마다 초안을 받고, **④ 검사**에서 검사 표를 보고 19번 서류 폴더로 넘깁니다. 검사와 글자 수는 Python과 똑같이 옮긴 [`web/apply-core.js`](web/apply-core.js)가 냅니다(검사가 두 결과를 맞대어 봅니다).

Claude Code 플러그인으로 쓸 때는 대화창에서 처음 한 번 설치합니다.

```text
/plugin marketplace add jhheo51-arch/saeroki
/plugin install saerok-apply@saeroki
```

## 쓰는 순서

| 단계 | 명령 | 하는 일 |
|---|---|---|
| 경험 장부 | `/saerok-apply:ledger [이력서 파일]` | 경험마다 ID·기간·직함·역할·판단 이유·행동 태그(한 일·설계안·계획)·수치(지표·시점·비교·출처)를 `ledger.md`에 정리합니다. AI가 정리한 칸은 '(AI 정리, 확인 전)'으로 남기고 내가 확인합니다 |
| 공고 분석 | `/saerok-apply:analyze <URL·붙여넣기·이미지> --company 회사` | 공고를 확인 날짜와 함께 `posting.md`에 저장하고, 요구·우대 역량·숨은 키워드(AI 해석)·회사 조사(출처 링크)·17번 [새록 사전](../17-saerok-dictionary) 용어를 `analysis.md`에 정리합니다 |
| 작성·첨삭 | `/saerok-apply:write --company 회사 [--edit 내 글]` | 문항마다 경험 후보 2~3개를 고르고, 사실 문장마다 장부 ID 주석을 단 초안을 새 판 파일로 씁니다. 검사를 통과하고 모든 문항이 확정이면 19번 서류 폴더로 넘깁니다 |
| 이력서·포트폴리오 | `/saerok-apply:resume`, `/saerok-apply:portfolio --company 회사 [--edit 내 파일]` | 공고에 맞춘 이력서·경력기술서, 포트폴리오를 장부 ID를 단 줄로 쓰거나 새 판으로 첨삭하고, 판마다 아래 '점검' 세 가지를 냅니다 |
| 점검·평가 | `/saerok-apply:review <파일> [--company 회사]` | "점검해 줘", "평가해 줘"라고 하면 아래 '점검' 세 가지로 이력서와 포트폴리오를 평가합니다 |

## 점검 (이력서·포트폴리오)

"점검해 줘", "평가해 줘"의 기준은 사용자가 정한 아래 요청 그대로입니다.

> 이력서와, 포폴을 오늘 이력서, 포폴 300장 보고 지친 채용담당자처럼 딱 5초만 훑어보고 어디서 읽기를 멈췄는지 말해줘. 채용 프로그램의 자동 필터가 돼서 100점 만점 기준 점수랑 나를 떨어뜨리는 키워드를 전부 찾아줘. 이 회사에서 나를 안 뽑으면 무조건 손해 보는 느낌이 들게 다시 써줘.

| 점검 | 내는 것 |
|---|---|
| ① 5초 훑기 | 첫 화면을 본 순서, 읽기를 멈춘 줄(반드시 하나 이상), 5초 뒤 남은 인상, 이 직무 지원자로 읽혔는지 |
| ② 자동 필터 | 100점 점수(필수 키워드 35, 우대 15, 경력 20, 숫자 근거 15, 표현과 형식 15)와 떨어뜨리는 키워드 전부. 스크립트 기준 목록과 AI 해석 목록을 나눕니다. 점수는 AI 판단이며 합격 예측이 아닙니다 |
| ③ '안 뽑으면 손해' 다시 쓰기 | 공고의 문제를 첫 줄에 두고 그 문제를 풀어 본 장부 사실을 붙인 첫 화면 다시 쓰기. 수치는 키우지 않고 줄마다 장부 ID를 답니다 |

결과는 지원 폴더의 `<회사>/<파일 이름>-YYYY-MM-DD.review.md`에 남습니다. ② 자동 필터의 스크립트 목록은 `saerok-apply check <이력서·포트폴리오>`(PRD 5.7절) 결과를 그대로 옮기고, AI 해석 목록과 나눠 적습니다.

공고는 이렇게 따로 표시합니다.

- 공고를 읽지 못하면 '읽기 실패'로 멈추고, 내용을 지어내지 않습니다.
- 캡처 이미지 공고는 옮긴 글을 내가 확인하기 전까지 분석하지 않습니다(구독 모드는 이미지를 넘길 수 없어 API 키 방식에서만 됩니다).
- 회사 조사를 못 했으면 '조사 안 됨'으로 두고, 초안에서 회사 사실을 쓰지 못하게 합니다.
- 17번 사전에 없는 용어는 '사전에 없음'으로 따로 표시합니다.

## 검사기가 보는 것

`saerok-apply check <초안>`은 같은 입력이면 늘 같은 결과를 냅니다. 오류가 있으면 종료 코드 2입니다. 파일 이름이 `resume-`, `portfolio-`로 시작하거나 첫 줄이 `# 이력서`, `# 포트폴리오`면 아래 '이력서·포트폴리오' 묶음으로 봅니다.

| 묶음 | 보는 것 |
|---|---|
| 글자 수 | 문항마다 공백 포함·공백 제외·바이트(UTF-8) 중 제한 기준으로 90~100% 적정, 짧은 칸 표 |
| 장부 대조 | 수치·기간·직함이 장부에 있는지, 지표 이름·단위·시점이 같은지, 설계안을 한 일처럼 썼는지, '처음'·'최초' 근거, 확인 전 장부 칸 |
| 출처 | 장부 ID 주석이 없는 사실 문장, 공고·회사 조사에 없는 숫자, 조사 안 됨인데 조사를 인용한 문장 |
| 다른 회사 | 지원 폴더의 다른 회사 이름(오류), 17번 사전 기업명(경고) |
| 문단 원칙 | 경험형 STAR 표시, 상황이 긴 문단, 팀 성과만 쓴 문단, 판단 이유·직무 연결 없는 문단, 추상 표현 |
| 문항 사이 | 같은 경험·같은 수치·거의 같은 문장 반복 |
| 커버리지 | 공고의 필수·우대 역량과 세부 업무가 어느 문항에 들어갔는지 |
| 판 관리 | 확정 문항의 본문·제목·상태가 이전 판과 달라졌는지, `[사용자 확인 필요]` 남은 곳 |
| 표기 규칙 | `style.md`의 금지어·바꿔 쓸 말·문장 길이·말투 |
| 용어 | 17번 사전에서 헷갈리기 쉬운 용어를 다른 뜻으로 쓴 곳 |
| 쓰기 규칙 | 마크다운이나 대화 복사 흔적(`**`, 목록 기호, `물론입니다` 같은 첫마디), 공고에 없는 영문 용어가 한 문장에 3개 이상(이메일, 주소 제외), 같은 문항이나 문서 안에서 거의 같은 문장 되풀이(경고). 핵심 요점과 논리 판단은 `skills/review` 점검이 봅니다 |
| 이력서·포트폴리오 (5.7절) | 줄마다 장부 ID, 장부에 없는 수치·기간·직함, '(가상 데이터)' 표시 없는 설계안 숫자, 쪽 수(이력서 1~2쪽, 포트폴리오 3~5쪽)와 숫자·프로젝트 카드 개수, 메타 칸(회사·직무·판·상태), 다른 회사 이름, 사진·생년월일·상세 주소, 공고 키워드 빠짐, 약한 표현, '프로젝트 3개' 같은 개수 주장과 실제 목록, 포트폴리오 한계 절, 같은 폴더 다른 문서와 연락처·기간·직함·날짜 표기 불일치 |

```bash
bash bin/saerok-apply init
bash bin/saerok-apply ledger
bash bin/saerok-apply analysis 가상커머스
bash bin/saerok-apply check ~/.saerok/apply/가상커머스/draft-2026-10-17.md
bash bin/saerok-apply diff <이전 판> <새 판>
bash bin/saerok-apply submit <초안> --dry-run
bash bin/saerok-apply check ~/.saerok/apply/가상커머스/resume-2026-10-20.md
bash bin/saerok-apply submit ~/.saerok/apply/가상커머스/portfolio-2026-10-20.md
bash bin/saerok-apply html ~/.saerok/apply/가상커머스/resume-2026-10-20.md --out 이력서.html
bash bin/saerok-apply privacy <파일...>
```

## 내 기록은 내 PC에만

경험 장부·공고·자기소개서는 이 저장소에 두지 않고 내 PC 지원 폴더(기본 `~/.saerok/apply/`, `SAEROK_APPLY_HOME`으로 바꿈)에만 저장합니다.

- 장부가 없거나 양식 그대로면 스킬이 먼저 "지원서를 작성하려면 경험을 전달해 주세요"라고 안내합니다. 가지고 있는 이력서, 경력기술서, 메모를 `경험자료/`에 넣거나 새록이 양식대로 `ledger.md`에 직접 쓰면 됩니다.
- 지원 폴더가 git 저장소 안이면 경고합니다.
- 저장·제출 전에 주민번호·전화번호·이메일 꼴을 찾아 앞 세 글자만 보여 줍니다.
- 초안은 늘 새 판 파일(`draft-YYYY-MM-DD.md`, 같은 날이면 `-2`, `-3`)로 쓰고, 19번 서류 폴더로 넘길 때도 같은 이름이 있으면 날짜를 붙여 덮어쓰지 않습니다.
- 이력서와 포트폴리오는 확정이고 검사 오류가 없을 때만 19번 서류 폴더에 `이력서-회사.md`, `포트폴리오-회사.md`로 넘깁니다. `html`은 주석을 뺀 한 단 HTML을 만들고, PDF는 브라우저 인쇄(PDF로 저장)로 만듭니다.
- 이 폴더의 [`examples/`](examples)는 모두 지어낸 가상 지원자·가상 회사입니다.

```text
~/.saerok/apply/
├─ ledger.md              경험 장부
├─ style.md               표기 규칙
├─ 경험자료/              내 이력서, 경력기술서, 메모(형식 자유, 장부 초안의 재료)
└─ 가상커머스/
   ├─ posting.md          공고 원문·출처·확인 날짜·상태
   ├─ analysis.md         역량 표·숨은 키워드·회사 조사·용어
   ├─ draft-2026-10-17.md 문항별 초안(사실 문장마다 장부 ID 주석)
   ├─ resume-2026-10-20.md    이력서·경력기술서(줄마다 장부 ID 주석)
   └─ portfolio-2026-10-20.md 포트폴리오(프로젝트마다 문제·한 일·결과·한계)
```

## 검사

```bash
python -m unittest test_saerok_apply
```

`data/terms-lite.json`은 17번 새록 사전 용어집을 줄인 사본입니다(플러그인은 저장소 밖에 설치되므로 함께 싣습니다). 17번 용어가 바뀌면 검사가 실패하니, 아래로 다시 만듭니다.

```bash
python -c "from pathlib import Path; from saerok_apply import terms; d=Path('../17-saerok-dictionary/data'); Path('data/terms-lite.json').write_text(terms.dump(terms.build(d/'terms.json', d/'catalog.json')), encoding='utf-8')"
```
