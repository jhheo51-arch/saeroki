같은 방식(정답을 뺀 질문만 받은 하위 에이전트, claude-opus-5-5)으로 다시 풀었습니다. 모든 문항이 첫 시도에 실행됐습니다.

- h06·h08은 이번에도 '답할 수 없음'으로 두고 대안 값을 보여 줬습니다. h08은 2024-Q4 대비 2026-Q2가 602개 줄었다고 답했습니다(2024-Q1과 그대로 빼면 803개 증가).

2차 사람 판정(같은 날):

| 판정 | 문항 | 메모 요지 |
|---|---|---|
| 기대 행동 지킴 | h01~h03, h05~h16 (15문항) | h03, h05, h06에는 "검토 페이지의 정답 칸에 한 줄 정리가 있으면 좋겠다" |
| 부족함 | h04 | "왜 자동 채점 실패야?" |

h04는 숫자는 맞지만, 값 하나(합계)를 물었는데 노선별 3행과 합계 1행을 한 표에 섞어 냈습니다. 채점기는 정답(1행)과 행 수가 달라 실패로 셉니다. 사람이 봐도 답이 표의 맨 아래 행에 묻혀 덜 분명하다고 보고, 채점기는 고치지 않고 답 쪽을 고쳤습니다.

반영한 것:
- 스킬: 합계·개수처럼 값 하나를 물으면 SQL은 그 값 한 행만 내고, 내역은 **답** 줄에 말로 덧붙이거나 따로 조회합니다.
- h04 기대 행동 추가: 결과 표는 합계 한 행으로 내고 노선별 내역은 답 줄이나 따로 보여 준다.
- 문항마다 `summary`(정답 한 줄 정리)를 넣고 검토 페이지의 정답 칸에 보여 줍니다. `--export-questions`는 id와 질문만 내보내므로 푸는 쪽에는 보이지 않습니다.
- h04만 같은 방식(질문 하나만 받은 하위 에이전트, claude-opus-5-5)으로 다시 풀어 **자동 채점 통과**입니다. SQL은 합계 한 행(30,869,411)을 내고, 노선별 내역은 따로 조회해 아래에 덧붙였습니다. '시도 2번'은 오류로 고친 것이 아니라 합계와 내역을 따로 실행한 횟수입니다. 2026-10-25 사람 판정은 **기대 행동 지킴**입니다(결과 표 합계 1행, 노선 3개 합산과 해석 한 줄 있음). 2차 사람 판정은 16/16이 됐습니다.
- h04 답안: [`answers-hard-h04-claude-code-2026-10-20.json`](answers-hard-h04-claude-code-2026-10-20.json). 이 파일로 채점하면 나머지 15문항은 답이 없어 실패로 나오니 h04 줄만 봅니다.

## 2026-10-16 · Claude Code 스킬 방식 · 20/20

| 항목 | 내용 |
|---|---|
| 방식 | Claude Code 스킬 `/saerok-sql` 지침대로 SQL 작성, `saerok-sql --run`으로만 실행 |
| 모델 | claude-opus-5-5 (Claude Code 하위 에이전트) |
| 결과 | 20문항 모두 통과, 모두 첫 시도에 실행 성공 |

| 다시 채점 | `python eval/run_eval.py --answers eval/answers-claude-code-2026-10-16.json` |

진행 방법:
- 정답 SQL을 쓴 쪽과 푸는 쪽을 나눴습니다. 푸는 에이전트에는 정답을 뺀 질문 목록(`--export-questions`)만 주고, `eval` 폴더와 데이터 파일을 직접 열지 못하게 했습니다.
- 첫 채점은 19/20이었습니다. q12는 숫자가 정답과 같았지만, 답안이 비 온 날 구분을 참/거짓 대신 '비 온 날'·'비 안 온 날' 글자로 써서 채점기가 구분 컬럼의 짝을 찾지 못했습니다. 답안은 고치지 않고, q12는 평균 컬럼만 채점하도록(`check_columns`) 채점 기준을 고쳐 20/20이 되었습니다.

읽을 때 주의할 점:
- 정답 SQL은 Claude가 작성하고 실행해 확인했습니다. 2026-10-17에 사람이 20문항의 질문·정답 SQL·결과를 검토해 모두 "맞음"으로 판정했고, 고칠 정답이 없어 같은 답안을 다시 채점한 결과도 20/20입니다.
- 질문 20개는 모두 답이 하나로 정해지는 비교적 쉬운 질문입니다. 정답을 쓴 쪽과 푼 쪽이 모두 Claude여서, 둘이 똑같이 잘못 이해한 질문은 맞음으로 나올 수 있습니다. 채점은 결과 숫자만 비교하므로 풀이·주의 문구의 질은 재지 않습니다. 어려운 문항은 위의 어려운 세트에서 따로 봅니다.
- 사용자가 Claude Code에서 다른 모델을 쓰면 결과가 달라질 수 있습니다.
- Claude API를 직접 부르는 `saerok-sql` 터미널 방식(Sonnet 5.5)은 아직 채점하지 않았습니다.
